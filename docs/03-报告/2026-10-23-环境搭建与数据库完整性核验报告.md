### 3.2 关于「快照 vs 现有库」——不导入

`sql/flycms_20260928_093335.sql`（2.9 MB / 84 表 / 535 条 INSERT）是 2026-09-28 的**旧基线**，比现有库少了整整一代数据结构：

- 快照有、现库无的 19 张表均为**已退役的旧硬编码模块**（`fly_article`、`fly_question`、`fly_topic`、`fly_share`、`fly_links`、`fly_message`、`fly_announcement` …），已被 `fly_cmodel_*` 动态模型表取代；
- 现库有、快照无的表包括 `fly_automation_rule`、`fly_comment`、`fly_content_version`、`fly_embedding`、`fly_cmodel_*` 全系等。

因此**导入快照会造成数据回退**（丢掉 10 月的模型/栏目/评论/自动化数据）。现有库才是最新且更完整的，本次未做导入。

### 3.3 已修复问题

#### (A) 超级管理员缺失 35 个权限节点（高危，功能性）

`fly_admin_permission` 共 241 个节点，超管组只授了 206 个。缺失的 35 个集中在：

- 模型 **13–18**（品牌 / 商品 / SKU / 购物车 / 订单 / 订单明细）的 list/add/edit/del 全部锚点；
- 上述 6 个 C 菜单节点 + `自动化规则` 菜单。

按项目既有规则「新增 `/api/**` 必须同时注册节点并授权，否则含超管在内全部 403」，这些菜单在后台点了会直接 403。

修复（先备份三张表到 `tools/_tmp_scripts/dbbackup/before_fix_20261023.sql`）：

```sql
insert into fly_admin_group_permission_merge(group_id,permission_id)
select 1,p.id from fly_admin_permission p
where not exists (select 1 from fly_admin_group_permission_merge m
                  where m.group_id=1 and m.permission_id=p.id);
```

**实测验证**（`tools/_tmp_scripts/probe_admin_perm.py`，真实登录态）：

```
未登录访问 list/14 -> HTTP 401（鉴权未被破坏）
登录成功
list/13 → 200 code=0    list/16 → 200 code=0
list/14 → 200 code=0    list/17 → 200 code=0
list/15 → 200 code=0    list/18 → 200 code=0
RESULT: PASS
```

#### (B) 5 个模型中文名为空

`fly_model` 中 `products` / `skus` / `carts` / `orders` / `order_items` 的 `name` 为 `''`（长度 0，非乱码）。这些名字会直接显示在后台菜单与前台栏目标签上。

### 3.5 风险项（未改动，建议排期）

| 项 | 数量 | 影响 | 建议 |
|---|---|---|---|
| 表字符集为 `utf8_general_ci`（= **utf8mb3**） | **50** 张，含 `fly_user`、`fly_config_web`、`fly_admin`、`fly_score_*`、`fly_user_*` | **无法存储 4 字节字符**（emoji、部分生僻汉字），写入会报错或截断。对内容站是硬伤 | 全库 `CONVERT TO CHARACTER SET utf8mb4`（需先全量备份；MySQL 5.7 需确认 `innodb_large_prefix` + `ROW_FORMAT=DYNAMIC` 以容纳 3072 字节索引） |
| MyISAM 表 | 4 张：`fly_areas`（**47,495 行**）、`fly_share_category`、`fly_retired_article_category_20260928`、`fly_retired_guide_20260928` | 无事务、崩溃后易损坏、表级锁 | 活跃表 `fly_areas` / `fly_share_category` 转 InnoDB |

```bash

E:/mysql57/mysql-5.7.44-winx64/bin/mysqld.exe --datadir=E:/mysql57/data --port=3306 --console

# 2) 后端（新开终端，环境变量已持久化）
cd E:/javawork/FlyCms/backend
mvn -o spring-boot:run -Dspring-boot.run.arguments=--server.port=80
```

> ⚠ 沿用既有铁律：`taskkill //PID <java> //F` 可能连带杀掉同进程树的 MySQL，停服后务必 `netstat | grep 3306` 复查。

可选（把 MySQL 注册为 Windows 服务，需管理员权限，避免每次手工起）：

```cmd
E:\mysql57\mysql-5.7.44-winx64\bin\mysqld.exe --install MySQL57 --defaults-file=E:\mysql57\my.ini
net start MySQL57
```
