**为什么按生命周期而不是按模块：**

- 这 8 篇文档几乎每篇都**横跨多个模块**——模板引擎方案同时动 backend + frontend + sql，收敛方案同时动 model + channel + article。按模块分（`后端/`、`前端/`、`模板/`）会导致同一篇文档无处安放，或被迫复制。
- 生命周期是三态分明的：**规划 = 还没做的**、**手册 = 怎么做**、**报告 = 已经做过的一次性产出**。新成员按这个顺序读，正好是"要做什么 → 怎么做 → 之前做过什么"。
- 模块维度不用丢：写进 `docs/README.md` 的索引表，用「涉及模块」一列打标签（`模板/模型/前端/运维`），检索时按标签过滤即可——比目录分层更灵活，且加新文档不用挪目录。
