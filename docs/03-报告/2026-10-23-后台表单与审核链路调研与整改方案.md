# 后台表单与审核链路 —— 调研与整改方案

> 调研时间：2026-10-23　范围：`frontend/apps/web-antd/src/views/system/**`（21 个页面 / 13 个弹窗）+ 后端 `ApiAuditController` / `ModelDataService`
> 结论口径：**先列证据，再定改法**。所有问题均给出文件行号与根因，不做"看起来不对"的模糊判断。

---

## 一、调研结论摘要

| 级别 | 数量 | 代表问题 |
|---|---|---|
| 🔴 阻断级（承诺了不存在的后端能力） | 3 | 驳回原因被后端丢弃、站内信从未实现、审核看不见正文 |
| 🟠 结构性（表单没有统一体系，必然长歪） | 4 | 手写 label 103 处、裸 checkbox 8 处、手填时间串 3 处 |
| 🟡 体验级（能用但难用） | 12 | 校验靠 toast、错误找不到页签、45 项平铺弹窗 |
| ⚪ 一致性与小瑕疵 | 6 | 状态字典三处不一致、模板多余字符 |

**一句话根因**：后台表单是"每个页面手写一遍 `<div class="mb-1 text-sm">标签</div>` + 控件"，缺少统一的 `Field/Form` 层，导致对齐、间距、必填标记、错误态只能靠人工自觉；审核链路则是**前端 UI 跑在了后端能力前面**（UI 承诺的驳回原因与站内信，后端根本没接收）。

## 二、🔴 阻断级问题（必须先修后端）

### P1. 驳回原因被后端直接丢弃 —— 用户填了，系统扔了

- 前端 `views/system/audit/index.vue:173` 传了 `reason`：
  ```ts
  await auditArticleApi(String(ids[0]), 2, rejectReason.value, modelId.value);
  ```
  `api/core/audit.ts:59` 也确实把 `reason` 放进表单体。
- **后端 `ApiAuditController.audit()`（第 86-96 行）与 `batch()`（第 103-114 行）的形参列表里根本没有 `reason`**，Spring 只按形参绑定，`reason` 静默丢失。
- 落到 `ModelDataService.updateStatus()`（第 638-650 行）**只做三件事**：改 status、写版本快照（remark 是硬编码的 `"状态切换→2"`）、发事件。**没有落原因、没有通知任何人**。
- 前端却弹 `message.success('已驳回，并已站内信通知作者')`（第 177 行）。

**后果**：审核员认真写的驳回理由一条都留不下来，作者也永远收不到。这是"UI 承诺了不存在的功能"，比样式难看严重得多。

**改法**（本次实施）：
1. 建迁移脚本 `sql/migrations/2026-10-23-audit-log.sql` 建表 `fly_content_audit_log`；
2. 后端两个接口接 `reason`，调用新的 `ModelDataService.updateStatusWithAudit(...)` 落日志；
3. 版本快照 remark 改成 `"审核驳回：<原因>"` / `"审核通过"`，让 G12 版本历史也能看到审核痕迹。

### P2. "站内信"在整个后端不存在

- 全库 grep `站内信|UserMessage|user_message|MessageService`：仅 `ApiBaseController:47` 一处**注释**提及，无任何实现、无数据表。
- 修正方式：把提示改成真实行为（"已驳回"），站内信另立需求，不在本次假承诺。

### P3. 审核页只能看到标题，看不到正文

- 审核列表 `columns`（`audit/index.vue:116-122`）只有：标题 / 作者ID / 状态 / 提交时间。
- 没有"查看内容"入口，审核员只能**对着标题点通过/驳回**。
- 后端无详情接口，`modelDataService` 的 `findDataById` 没有对外暴露给审核用。

**改法**：新增 `GET /api/system/audit/detail`（modelId + id → 整行，含 `content`），审核页加详情抽屉。

## 三、🟠 结构性问题（表单没对齐的真正根因）

### S1. 手写标签 103 处 —— 没有任何对齐保障

```
views/system/website/index.vue      11 处
views/system/channel/channel-modal  11 处
views/system/modeldata/form-modal   10 处
views/system/menu/menu-modal         8 处
views/system/form/field-drawer       7 处
views/system/block/item-modal        7 处
views/system/area/index.vue          7 处
... 共 17 个文件 103 处
```

模式统一是：
```vue
<div>
  <div class="mb-1 text-sm"><span class="text-red-500">*</span> 栏目名称</div>
  <Input v-model:value="channelName" />
</div>
```
问题：
- 标签是 `<div>` 不是 `<label>`，**点击标签不聚焦控件**，无障碍缺失；
- 必填红星靠人肉加，10 处里有 3 处该加没加；
- 没有错误态容器，校验只能 `message.warning()` 弹 toast；
- 标签和控件的间距写死 `mb-1`，与页面其他区块不一致 → 视觉上"没对齐"。

**改法**：抽出 `views/system/_shared/field-item.vue`（标签 + 必填星 + 提示 + 错误区四位一体），全部替换。

### S2. 裸 HTML 控件 8 处

| 文件 | 内容 |
|---|---|
| block/block-modal.vue:119 | `<input type="checkbox" id="blk-status">` |
| form/form-modal.vue:109/113/117 | 三个裸 checkbox（验证码/审核/启用） |
| form/field-drawer.vue:202 | 裸 checkbox |
| images/index.vue:91 | 裸 checkbox（只看孤儿） |
| menu/menu-modal.vue:174 | 裸 checkbox |
| template/skin-modal.vue:202 | 裸 checkbox |

原生 checkbox 与 antd 的 Switch/Checkbox 尺寸、颜色、focus 环都不一致，在同一个表单里并排就是"没对齐"的直接观感。→ 全量换 `<Switch>` / `<Checkbox>`。

### S3. 手填时间字符串 3 处

- `modeldata/form-modal.vue:747` 定时发布时间 `Input placeholder="yyyy-MM-dd HH:mm:ss"`
- `block/item-modal.vue:180/184` 上线/下线时间同上

手填 `yyyy-MM-dd HH:mm:ss` 是典型的"能用但极易填错"：填成 `2026/10/23 10:00` 或 `2026-10-23` 都进得去库，前端不报错，定时发布任务扫不到 → **静默失效**。→ 换 `DatePicker show-time`，`value-format` 固定。

### S4. `<Input type="number">` 当排序框 3 处

`block/item-modal.vue:188`、`menu/menu-modal.vue:169`、`area/index.vue:538` → 换 `InputNumber`（有步进器、有 min/max、值类型正确）。

## 四、🟡 核心页面专项

### 4.1 内容发布/编辑页 `modeldata/form-modal.vue`（991 行，本次改造重点）

| 编号 | 问题 | 证据 | 影响 |
|---|---|---|---|
| C1 | **校验用 toast 逐个弹，且报错后不跳转** | `onConfirm` 第 462-481 行 `for` 循环里 `message.warning(...); return;` | 用户在「基础信息」点保存，若必填字段在「SEO 设置」页签，只看到一句 toast，看不到红框在哪 |
| C2 | 只校验顶层字段 | 同上循环 `for (const f of topFields.value)` | GROUP/REPEATER 子字段的 `isRequired` 完全不生效 |
| C3 | 字段渲染块复制 3 份 | 第 751-845（base 页签）、861-955（自定义页签）、769-830 / 879-940（GROUP/REPEATER 子字段） | 991 行里约 250 行是复制粘贴，改一处要改三处，是继续劣化的源头 |
| C4 | 「初始化编辑器」按钮 | 第 854 行 `values.content = ' '` | 把实现细节暴露给用户，用户不知道该不该点 |
| C5 | AI 三按钮共用一个 `aiBusy` | 第 245、272 行 | 点「AI 标题建议」，三个按钮同时转圈 |
| C6 | AI 摘要/关键词按钮放在标题下方 | 第 681-686 行 | 生成结果却写进 SEO 页签的字段，按钮与结果两地分居 |
| C7 | 状态下拉含「未通过」 | 第 708-713 行 | 新建内容时选「未通过」语义荒谬；且缺「草稿」 |
| C8 | 定时发布时间手填 | 第 747 行 | 见 S3 |
| C9 | 编辑回显失败兜底用列表行 | 第 579 行 `row = data.record` | 列表是投影列（不含 content/长字段），会静默丢值 |

**改法**：
1. 抽 `model-field-item.vue`，三份渲染块合一（-250 行）；
2. 校验结果结构化：`errors: Record<fieldName, string>` → 内联红字 + 页签红色角标 + 自动切到第一个出错页签 + 聚焦首个错误控件；
3. 子字段纳入校验（递归 GROUP/REPEATER）；
4. 定时发布换 DatePicker，且必须晚于当前时间；
5. 删除"初始化编辑器"按钮，编辑器空值时自动初始化；
6. AI 按钮独立 loading（`aiTask: 'title'|'summary'|'keywords'|''`），摘要/关键词按钮移到 SEO 页签；
7. 状态选项按场景收敛（新建：草稿/发布/定时；编辑：+未通过），并与「先审后发」开关联动默认值；
8. 回显失败改为明确报错并关闭抽屉，不静默降级。

### 4.2 字段编辑弹窗 `model/field-modal.vue`（988 行）

- **45 个 schema 项全部平铺单列**：填一个字段要从"字段名"滚到"预设色板"，中途还有 6 个不同类型的"时间格式/选项布局"同名项。
- **`w_format` 在 schema 里出现两次**（第 512 行给 date、第 529 行给 datetime），靠 `dependencies.show` 互斥，但 `updateSchema` 按 fieldName 匹配时会打架。
- **类型切换后残留值会入库**：`dependencies.show` 只隐藏不清除，先选 textarea 填了 `w_rows=10` 再改为 input，`w_rows` 仍在 values 里。虽然 `serializeWidgetConf` 按类型 switch 会忽略，但 `w_checkedText` 之类跨类型同名项有污染风险。

**改法**：按 4 组重新组织（`useVbenForm` 的 `wrapperClass` 分组 + Collapse）：
- 基础：字段名 / 类型 / 显示名 / 选项卡 / 占位提示 / 排序
- 校验与选项：必填 / 长度上限 / 正则 / 最值 / 值唯一 / 候选来源 / 选项 / 字典
- 高级：绑定模型 / 聚合配置 / 公式 / Lookup / 条件显隐
- 控件外观：按类型联动的 `w_*`（合并成一个动态分组）

## 五、⚪ 一致性问题

### T1. 内容状态字典三处不一致

| 位置 | 值集 |
|---|---|
| `modeldata/form-modal.vue:708-713`（发布状态下拉） | 0待审核 / 1发布 / 2未通过 / 4定时发布（**缺 3 已删除**） |

**改法**：抽 `constants/content-status.ts` 单一来源，三处引用。

### T2. 后台内容默认状态不合理

`form-modal.vue:65` 新建时 `status: '0'`（待审核）。若站点关了「先审后发」，管理员在后台亲手新建的内容仍然是"待审核"，前台不展示——需要用户再手动改成"发布"。

**改法**：新建默认值跟随审核开关（开→待审核，关→发布）。

## 七、验收口径（不写魔数，只断言不变量）

1. **后端**：`GET /api/system/audit/detail` 能返回 `content` 字段；驳回后 `fly_content_audit_log` 有 1 行且 `reason` 与输入一致、首尾空格已 trim。
2. **内容发布页**：
   - 保存时若有必填未填 → 该字段下方出现红字、所在页签出现红色角标、视图自动切到该页签；
   - 子字段（GROUP/REPEATER 内）必填为空 → 同样被拦下；
   - 定时发布时间选择器不允许选过去时间。
3. **审核页**：点「查看」能看到正文；驳回后「历史」能看到原因；页面上不再出现"站内信"字样。
4. **全局**：`grep -rn 'type="checkbox"' views/system` 命中 0；`grep -rn 'placeholder="yyyy-MM-dd HH:mm:ss"'` 命中 0。
5. **回归**：`pnpm build:antd` 通过；`tools/e2e_template_check.py` 保持 PASS（前端改动不碰模板，仅防回归）。

### 9.3 安全说明（新增代码的 XSS 边界）

审核详情要把**用户投稿**的正文渲染成富文本。投稿内容未经服务端 jsoup 清洗，

危害远大于前台）。因此新增 `utils/sanitize-html.ts`：零依赖白名单清洗
（标签白名单 + 属性白名单 + `on*` 全禁 + `href/src` 协议白名单 + iframe 域名白名单 + `rel=noopener`），
依赖 `<template>.innerHTML` 的惰性文档特性（不执行 script / 不触发 onerror）。

### 10.2 手写标签 43 → 1

`tools/_tmp_scripts/fielditem_migrate.py`（前端目录下）做行式转换：`<div><div class="mb-1 text-sm…">标签</div><控件/></div>` → `<FieldItem label="…" …>`。三道保险：

1. 闭合标签按**出现次数**计数（此前只匹配整行 `</div>`，行内 `<div …>x</div>` 的闭合漏算，会把块尾算错、**静默吞掉模板后半段**——`area/index.vue` 曾被从 567 行截到 558 行、模板引用全丢）；
2. 开合标签不成对**拒绝落盘**；
3. 标签内含 `<` / `>`（如 `<template v-if>`）跳过。

另需注意：`Path.read_text()` 的 universal newlines 会把 CRLF 归一成 LF 制造大量无关 diff，脚本改用 `open(..., newline="")` + `readlines()` 保留原行尾。

结果：`website/index.vue` 11、`area/index.vue` 7→1（多分支标签改 computed）、`automation` 5、`debug-chain-modal` 6、其余零星若干 → **总计剩 1 处**（`channel-modal.vue` 注释文字）。脚本幂等（复跑 0 改动）。

### 10.3 服务端 jsoup 清洗（写侧 + 存量）

| 项 | 落地 |
|---|---|
| 工具类 | `core/utils/ContentSanitizer.java`：`Safelist.relaxed()` 基线 + 显式增补（section/article/figure/figcaption/hr/iframe/video/audio/source/embed、class/style/id、iframe 域名白名单、`rel=noopener`）+ 二次收口（非白名单媒体域名 `remove()`、`a[target=_blank]` 补 `rel`）。**清洗失败按「宁可空、不可脏」返回 null 并 warn** |
| 写侧 | `addData` / `updateData` / **`ownerUpdate`** 三处 content 入口全部过 `sanitizeContentIfEnabled()`，配置键 `fly_content_sanitize`（缺省开启，`1`=开） |
| 存量 | `POST /api/system/tools/sanitize/backfill?modelId=&batchRows=`（权限 900314）按模型分页扫描，只对确有变化的行 UPDATE，**幂等**（复跑 `updated: 0`） |
| 类型边界 | `FieldTypeEnum.EDITOR` 不建独立列、统一走主表 `content` 通道 → 清洗点只有 `content` 一处 |

**为什么必须做**：富文本正文在 FreeMarker 侧是 `${info.content}` 原样输出（必须如此），
所以正文里带 `script` / `on*` / `javascript:` 就是一条完整的**存储型 XSS** 通道，
前台侧栏渲染侧清洗只能保护自己，拦不住别人访问同一个页面。
