# 依赖漏洞修复报告（后端 + 前端）

- 日期：2026-10-23
- 范围：`backend/pom.xml`（Maven 运行时依赖）、`frontend/pnpm-workspace.yaml`（pnpm overrides / catalog）、JDK 运行时
- 结论：**后端 18 条漏洞全部清零；前端 53 条降到 4 条（critical 由 3 → 0），剩余 4 条上游均未发布修复版本**；JDK 那条（CVE-2026-91403）目前无任何开源发行版提供修复构建。

## 一、扫描方法（为什么要换方法）

不是"照着印象列几个包"，而是先取**真实生效的依赖版本**再比对漏洞库：

| 侧 | 取版本 | 比对 |
|---|---|---|
| 后端 | `mvn dependency:list -DincludeScope=runtime` → 141 个运行时坐标 | OSV `POST /v1/querybatch`（分批 400）+ 命中项逐个取 `/v1/vulns/{id}` 拿 fixed 版本 |
| 前端 | `pnpm-lock.yaml` + `pnpm audit --json` | npm advisory 库 |

两个容易踩的坑（都已在脚本里处理）：

1. **不能扫 `~/.m2`**。本地仓库混着历史版本（`mysql-connector-j` 8.0.33 与 8.2.0 并存、`jsoup` 1.17.2 与 1.23.1 并存），扫 m2 会把"根本没进 classpath"的版本报成漏洞，方向直接跑偏。
2. **OSV 没有 `/v1/batch`**（404），批量接口是 `/v1/querybatch`，且只回漏洞 ID，明细要再按 ID 取。

脚本：`tools/_tmp_scripts/osv_deps.py`（`--` 后接依赖清单路径）。

### 2.2 处置

改动集中在 `backend/pom.xml` 一处，分三类：

**A. 覆盖 Boot BOM 版本属性**（属性名取自 `spring-boot-dependencies-4.1.1.pom` 实际存在的，写在 `<properties>` 即生效，不需要 exclude 再重声明）

```xml
<tomcat.version>11.0.25</tomcat.version>       <!-- 3 个 CRITICAL -->
<freemarker.version>2.3.35</freemarker.version> <!-- 前台全靠它渲染，属直接暴露面 -->
<jackson-bom.version>3.1.7</jackson-bom.version>
```

Jackson 取 **3.1.7** 而不是 3.2.3：3.1.7 已满足全部 7 条修复下限，且不跨 minor，避免和 Boot 4.1.1 的 Jackson 3.1.x 集成点产生 API 漂移。

**B. 裁掉永不加载的传递依赖**（quartz → c3p0 + mchange + HikariCP-java7）

```xml
<dependency>
  <groupId>org.quartz-scheduler</groupId><artifactId>quartz</artifactId><version>2.3.2</version>
  <exclusions>c3p0 / mchange-commons-java / HikariCP-java7</exclusions>
</dependency>
```

安全性论证（不是"看着没用就删"）：本项目连接池是 **Druid**，调度走 Spring 的 `SchedulerFactoryBean` + `AdaptableJobFactory`（`module/job/config/ScheduleConfig.java`），quartz 只跑内存态 `SimpleThreadPool`，**从不实例化 c3p0 连接池** —— c3p0 只有在显式配置 `C3P0ConnectionProvider` / `JobStoreCMT` 时才会被类加载。`HikariCP-java7` 同理（Boot 已通过 `starter-jdbc` 提供 HikariCP 7.0.2），留着反而可能版本打架。
注意：升到 Boot 管理的 quartz 2.5.2 并不能解决问题 —— 2.5.2 依赖的 c3p0 是 0.10.1，仍在受影响区间，所以只能靠 exclusion。

**C. 直接升版本**：`jsoup 1.23.1 → 1.23.2`；`org.json` 从阿里 SDK 的传递依赖改为显式声明 `20231013`（同时 exclude 掉 SDK 自带的 20170516，否则会被重新拉回）。

### 2.3 结果

```
解析到 138 个运行时依赖
=== 命中 0 条 ===
```

依赖数从 141 降到 138（c3p0、mchange-commons-java、HikariCP-java7 已移出）。

## 三、前端：53 条 → 4 条

### 3.1 修复前

`pnpm audit`：**53 条 advisory / 15 个包 / 3 critical、20 high、25 moderate、5 low**。

关键点：这些包在 `pnpm-lock.yaml` 里**已经锁在受影响区间**（axios 1.19.0、vite 8.2.2、undici 7.29.0、tinypool 2.1.0 …）。只改 catalog 的 `^` 范围**不会生效** —— 锁文件已满足范围就不会重新解析，必须用 `overrides` 强制。

### 3.2 处置（`frontend/pnpm-workspace.yaml`）

沿用文件里既有的写法：key 用「包名@受影响区间」，只抬受影响的版本线，不波及其它主版本。

|---|---|---|---|
| axios | <1.20.0 | ^1.20.0 | 12 |
| vite | <=8.3.2 | ^8.3.3 | 18 |
| undici | 7.x <7.29.1 | ^7.29.1 | 10 |
| brace-expansion | 2.x <2.1.7 | ^2.1.7 | 3 |

## 四、JDK：CVE-2026-91403 目前无法修复

- 漏洞：JSSE，CVSS **9.1**，2026-10-21 带外发布（Oracle Security Alert）。可远程、无需认证、无需用户交互，影响机密性与完整性。
- Oracle 给出的修复构建是 **25.0.5.0.2**（另有 8u512 / 11.0.33.0.2 / 17.0.21.0.2 / 21.0.13.0.2 / 27.0.1.0.2）。
- 实测各开源发行版最新版本（2026-10-23 查询）：

| 发行版 | 25 线最新 GA |
|---|---|
| Adoptium Temurin | **25.0.4.1**（25.0.5 只有 `+1…+7-ea-beta` 早期构建） |
| Azul Zulu | **25.0.4.1** |

即：**没有任何开源发行版提供 ≥25.0.5 的正式构建**，装不上修复版。现状是"能跑但未修复"，等 Adoptium 发布 25.0.5 / 25.0.6 GA 后升级即可（升级动作只是替换 `C:\java` 下的 JDK 目录 + `JAVA_HOME`，无代码改动）。
不建议用 `25.0.5-ea-beta` 顶替 —— EA 快照早于这次带外修复，且不适合生产。
