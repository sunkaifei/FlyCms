## P0 — 阻塞性缺陷（换肤安全底线）

### P0-1 配置空值更新会生成非法 SQL

| 项 | 内容 |
|---|---|
| **问题** | `ConfigDao.xml` 的 `updagteConfigByKey` 中 `<set>` 内四个字段都带 `!= ''` 判断。当**要写的值本身是空串**（或调用方只传 keycode）时，SET 子句整体为空 → 生成 `update fly_config_web where keycode=?` → SQL 语法错误。任何"把某个配置清空"的后台操作都会 500 |
| **改动文件** | `backend/src/main/java/com/flycms/module/config/dao/ConfigDao.xml`；`backend/.../config/service/ConfigService.java` |
| **修法** | ① 条件从 `!= ''` 改为 `!= null`（空串必须能被写进去）；② `<trim prefix="set">` 末尾追加恒定项 `keycode=#{keycode}`（写回自身，值不变）作为**兜底**，保证 SET 子句永不为空；③ service 层对 `null` value 做防御（转空串） |
| **验收标准** | ① 后台保存空串配置不再 500；② 库中该键值确为空串（HEX 为空）而非 NULL |
| **实测结果** | ✅ **通过（2026-09-28）**<br>· 缺陷机制复现：直连库执行 `update fly_config_web set where keycode='phone'` → `ERROR 1064 You have an error in your SQL syntax`<br>· 修复后：`POST /api/system/website/save`（`phone=`）→ `200 {"code":0,"message":"已保存 1 项站点设置"}`（修复前此处必 500）<br>· 库查证：`phone` 值为空串（`hex()` 返回空），非 NULL —— 空值确实落了库<br>· 现场已还原（`phone` 恢复为 NULL） |
| **状态** | `[x]` |

### P0-2 切换主题会写坏回滚点，导致一键回滚永久失效

| 项 | 内容 |
|---|---|
| **问题** | `ThemeSwitchService.enable()` 先 `updagteConfigByKey(PREV_KEY, prev)` 再写新主题，全程**不校验 `prev` 是否是真实存在的主题**。若当前主题指向一个不存在的目录（新库 / 手工改过 `pc_theme` / 主题被删），回滚点就是脏数据 → 之后每次"一键回滚"都只返回"没有可回滚的历史主题"，**回滚能力永久失效** |
| **改动文件** | `backend/.../template/service/ThemeSwitchService.java` |
| **修法** | ① `enable()` 增加前置校验：`prev` 必须能 `registry.getTheme(prev)` 命中，否则**中止切换**（不写任何配置），返回明确错误"当前主题状态异常，无法确定回滚点"；② `rollback(reason)` 在无可回滚点时，日志区分"失败且未变更"，避免误导；③ 校验通过后再写 `pc_theme_prev`，保证写入的回滚点一定可用 |
| **验收标准** | ① 正常切换：`pc_theme` = 新主题，`pc_theme_prev` = 旧主题，两者都是磁盘上真实存在的目录；② 把 `pc_theme` 手工改成不存在值后再调切换 → 返回失败、`pc_theme` **未被改动**、回滚仍可用 |
| **实测结果** | ✅ **通过（2026-09-28）**<br>· 人为把 `pc_theme` 置为 `__no_such_theme__` 后调 `enable?code=wpdemo` → 返回 `-1 当前主题状态异常（pc_theme=__no_such_theme__），无法确定回滚点，已中止切换`<br>· 复查库：`pc_theme` 仍为 `__no_such_theme__`（**未被改动**）、`pc_theme_prev` 仍为 `defalut`（有效回滚点未被污染）<br>· 此时调 `POST /api/system/theme/rollback` → `已回滚到上一主题：defalut`，首页恢复 200，证明脏状态下仍能自救 |
| **状态** | `[x]` |

### P0-3 探活是假的：切换后不做任何真实请求

| 项 | 内容 |
|---|---|
| **问题** | 方案 §6.4 承诺"切换后自动请求首页/列表/详情，非 200 则回滚"，实际 `enable()` 只判断 `registry.locate(code,"index.html") != null`——即**磁盘文件是否存在**，而这一步在预检 `checkCompatibility()` 里已经做过。全程**零 HTTP 请求**，"探活"名存实亡：模板语法错、标签不存在、运行期异常导致的 500 一个都拦不住 |
| **改动文件** | 新建 `backend/.../template/service/ThemeHealthChecker.java`；改 `ThemeSwitchService.java` |
| **修法** | 用 **Hutool `HttpUtil`**（项目已有依赖 5.8.47；不要用 JDK HttpClient——本项目踩过它对 Jetty chunked 响应抛 `READING_DATA` 的坑）自请求 `http://127.0.0.1:${server.port}`：<br>① **硬探活**首页 `/`：非 200 **或**响应体含 `FreeMarker template error`（DEBUG 模式会把模板错误内联输出成 200，只看状态码会漏）→ 判定失败并回滚；<br>② **软探活**列表/详情：能从栏目数据推导出 URL 才探，异常只记 warn 不回滚（避免因栏目为空误伤）；<br>③ 自请求带超时（8s）且**不带** `__skin=` 预览参数，走真实全局主题 |
| **验收标准** | ① 正常主题切换 → 探活通过，返回成功；② 故意造一个 `index.html` 里写坏标签的主题 → 切换后探活失败、**自动回滚**到旧主题、`pc_theme` 回到原值；③ 探活期间应用日志能看到 `[theme-probe]` 记录 |
| **实测结果** | ✅ **通过（2026-09-28）**<br>· 放行路径：`enable?code=defalut` → `200 {"code":0,"message":"主题已启用：defalut"}`、`warnings:[]`（探活**不会误伤**正常主题）<br>· 拦截路径：造坏主题 `_probe_bad`（`index.html` 写 `${__probe_undefined__.foo}`）→ 返回 `探活失败：/ 返回 200，但页面内含 FreeMarker 报错（模板未能正常渲染）；已自动回滚到 defalut`；库中 `pc_theme` 已回到 `defalut`，首页复探 200 且无报错<br>· ⚠️ **关键**：坏主题返回的是 **HTTP 200**（FreeMarker 默认 DEBUG 异常处理器把报错内联进页面，状态码不变），**任何"只看非 200 就回滚"的实现都会把它放行成线上白屏**，响应体检测是必需的<br>· 实战价值：自测主题 `wpdemo` 同样被探活拦下（也是 200+报错）——按原伪探活逻辑把它切上去就是白屏 |
| **状态** | `[x]` |

## P1 — 主题市场门面 + 生产参数

### P1-1 当前主题没有 `theme.json`，主题市场卡片信息全空
`views/templates/pc_theme/defalut/` 下无 `theme.json`，`ThemeRegistry.defaultTheme()` 兜底后：名称=目录名 `defalut`，版本/作者/缩略图全空，描述是"（未提供 theme.json，已自动生成默认清单）"。主题市场是产品门面，点进去一片空白。
**修法**：给 `defalut` 补 `theme.json`（name/version/author/description/thumbnail/supports），缩略图上 `docs/assets/preview/首页.png` 对应的静态资源路径。**状态** `[ ]`

### P1-2 测试主题 `wpdemo` 混在生产主题目录
`views/templates/pc_theme/wpdemo/` 是 WordPress 转换器的自测主题（`theme.json` 自述"用于转换器自测"，还带 `CONVERT-REPORT.json` 构建产物），主题市场会把它当正常主题列出；它只有 `index/detail/parts`，一旦被启用多数页面回退 index。
**修法**：移到 `views/templates/_testdata/wpdemo/`（`ThemeRegistry` 只扫 `pc_theme` 下一级目录，移出即不再被登记），转换器自测改为从 `_testdata` 取。**状态** `[ ]`

### P1-3 生产环境 FreeMarker 缓存仍是关闭状态
`application.yml:22` `spring.freemarker.cache: false`（开发配置）。§10 要求生产开 `true`；且"保存模板后 `removeTemplateFromCache` 主动失效"这段逻辑在 `cache=false` 下**毫无意义**（没有缓存可失效）。
**修法**：改为按 profile 取值（dev `false` / prod `true`），并确认保存模板、切换主题两条路径都能正确失效缓存。**状态** `[ ]`

## P2 — 补齐缺失的 UI 入口与指派能力

### P2-1 主题市场缺「导入 / 导出 / 删除」三个按钮
后端 `ThemeService.importSkin()` / `exportSkin()` 早已存在，前端 `views/system/theme/index.vue` 只有：启用、预览、派生模板、创建子主题、回滚上一主题 —— 后端的导入导出**没有任何入口**。
**修法**：工具栏补三个按钮 + 上传/下载/二次确认弹窗。**状态** `[ ]`

### P2-2 栏目级指派的 `target_id` 口径不一致
`TemplateResolver.assignedTemplate()` 的 CHANNEL 级用 `ctx.getChannelDir()`（如 `news`）当 `target_id`，而方案 §5.3 表定义写的是"栏目 **ID**"。一旦按文档做出栏目指派 UI 并写数字 ID，查询将**永远不命中**。
**修法**：先定口径（建议统一为目录名，与前台路由一致，避免栏目重建后 ID 漂移），改代码注释与方案 §5.3 表格对齐，再写 UI。**状态** `[ ]`

### P2-3 栏目页、模型页没有模板指派入口
§8.3 设计了"内容 / 栏目 / 模型"三处下拉选模板，全仓搜索只有 `modeldata/form-modal.vue` 一处调用了 `assignTemplateApi('CONTENT',…)` —— **只做了 1/3**。
**修法**：`channel/` 列表页与 `model/` 列表页补指派下拉，复用既有接口。**状态** `[ ]`

### P2-4 单页栏目（CHANNEL_PAGE）的指派不生效
`assignedTemplate()` 只对 `DETAIL` / `LIST` / `INDEX` 返回值，`CHANNEL_PAGE` / `SEARCH` / `TAG` / `ERROR` **一律返回 null**，而 §5.1 把"DB 指派"列为单页栏目的第一优先级。
**修法**：补 `CHANNEL_PAGE` 分支（依赖 P2-2 口径），SEARCH/TAG/ERROR 视 P3-1 决策再定。**状态** `[ ]`

### P2-5 DB 与磁盘不同步靠 60s 惰性扫描，不是"启动时校验"
方案 §16 风险 3 的对策写"启动时扫描校验并修正"，实际是 `ThemeRegistry` 的 `TTL = 60_000` 惰性扫描 + `themeDao.upsert`。
**修法**：要么补一个启动期 `ApplicationRunner` 做一次主动登记（同时把 `wpdemo` 之类的脏数据清出 `fly_theme`），要么把方案文档改成"惰性 60s"——**二选一，别两头都不认**。**状态** `[ ]`

## 验证手册（P0 验收用）

### 1. 起环境

```bash
# MySQL（绿色版，需手动起；用完 kill）
E:/mysql57/mysql-5.7.44-winx64/bin/mysqld.exe --defaults-file=E:/mysql57/my.ini --console
```

### 2. 登录（e2e 脚本方式）

- `GET /captcha/default` 返回 **4 帧 GIF 动画**验证码，PIL 读首帧必错：需逐帧 `ImageChops.darker` 合帧 → autocontrast → 阈值二值化再识别
- `POST /api/auth/login`，参数 `admin_name` / `password` / `captcha`，账号 `flycms` / `admin123`
- 请求必须**手工构造 Cookie 头**（`JSESSIONID`）；用 `http.cookiejar` 会自动失败并报"验证码错误"

### 3. 关键端点

| 用途 | 端点 |
|---|---|
| 兼容性预检 | `GET /api/system/theme/check?code=<code>` |

| 一键回滚 | `POST /api/system/theme/rollback` |
| 预览（仅本会话） | `GET /?__skin=<code>` |

### 4. 库表速查

| 用途 | 位置 |
|---|---|
| 当前主题 / 上一主题 / 调试开关 | `fly_config_web` 的 `keycode` / `keyvalue`（键：`pc_theme`、`pc_theme_prev`、`template_debug`） |

> 连库导入带中文的 SQL 必须加 `--default-character-set=utf8mb4`，否则中文真实乱码（不是显示问题）。

### 附带修复（同批次发现，不在原报告清单内）

| 项 | 内容 |
|---|---|
| `ThemeDao.xml` 的 `updateCurrent` | 原实现把「清 0」和「置 1」两条 SQL 用分号拼在一条语句里。MySQL 驱动默认 `allowMultiQueries=false`、Druid wall 也禁止多语句 → 该语句**必然抛异常**；而调用方是 `catch (Exception ignored)` 静默吞掉 → `fly_theme.is_current` 长期未正确更新且无日志可查。已拆成两条独立 SQL（`clearCurrent()` + `updateCurrent()`），并把静默 catch 改为警告日志。 |
| `ThemeHealthChecker` fail-open | 探活请求**没到达应用**（连接拒绝/超时）时，判定为"探活机制自身不可用"（`conclusive=false`），**不回滚**、只告警。否则探活自身出问题会导致任何主题都切不上去，比不做探活更糟。 |
| 回滚后复探 | 回滚完成后**再探一次**，确认服务真的恢复；否则"回滚了但还是白屏"会被当成功返回给管理员。 |
| 列表页软探活 | 取"第一个可见列表型栏目"的 `/{channelDir}`。路径**不补尾斜杠**——Spring 6 默认不匹配尾斜杠，前台栏目路由是 `/{channelDir}`，带斜杠会 404 误判。详情页探活未做（需内容数据推导 URL，留待 P2）。 |
