## 1. Q1 媒体库多尺寸（对标 WP 上传自动裁剪 + srcset）

### 1.1 现状

- `fly_images` 只有原图一行（img_url/img_width/img_height），无多规格；
- 前台模板输出原图 URL，无 srcset——大图在移动端浪费流量、LCP 差；
- 缩放能力已有：`ScaleImageUtils.resize`（但写死 jpg 输出，PNG 透明度会丢——不可直接用）；
- 上传通道：管理端 `/api/system/images/upload`（W 批次）+ 前台 `/ucenter/upload` 等编辑器通道（不落 fly_images 行）。

### 1.2 设计

**存储**：`fly_images` 加 `sizes` text 列，JSON 数组（从小到大）：

```json
[{"n":"thumb","u":"/upload/admin/20261002/x_150.png","w":150,"h":112},
 {"n":"mid","u":"/upload/admin/20261002/x_320.png","w":320,"h":240},
 {"n":"large","u":"/upload/admin/20261002/x_768.png","w":768,"h":576}]
```

- 规格：thumb 150w / mid 320w / large 768w；**只缩不放**（原图小于目标规格则跳过该档）；
- 保持宽高比与原格式（png 保透明、gif 首帧、jpg 质量 0.85）；
- 原图 URL 恒为 `img_url`，sizes 是补充——旧记录无 sizes 时读侧回退单 URL，完全向后兼容。

**生成时机**：
- 管理端直传（/api/system/images/upload）：落原图后即生成；
- 前台上传通道（/ucenter/upload 等编辑器通道）：同样接多尺寸生成（文件已落盘，补 sizes 计算与 fly_images 行——编辑器通道历史上不落行，本批一并修复：编辑器上传也登记 fly_images，进附件库统一管理）；
- 存量图片不回填（可后续批处理，非本期）。

**读侧**：
- `fly_images` 查询（findImageUrls/findByIds/batch）带出 sizes；
- `ModelDataService.expandAttachments` 新增：按 sizes 生成 `{field}Srcset` 字符串（`"u 150w, u 320w, u 768w"`，按宽升序）+ 行内 `sizes` JSON 透传；
- 模板用法：`<img src="${info.thumbnailUrl}" srcset="${(info.thumbnailSrcset)!''}" sizes="(max-width: 768px) 100vw, 768px">`；
- 附件批量回显接口（batch）同样返回 sizes，管理端编辑不受影响。

**安全**：尺寸生成纯本地图像处理（ImageIO），无外部输入拼路径；目标规格写死白名单（150/320/768），不接受用户指定尺寸。

### 1.3 改动清单

| 文件 | 改动 |
|---|---|
| `sql/migrations/2026-10-02-media-sizes.sql` | ALTER fly_images ADD sizes text（幂等说明） |
| `module/images/model/Images.java` | +sizes（String JSON） |
| `images__ImagesDao.xml` / `ImagesDao.java` | 列带出 |
| `module/images/service/ImagesService.java` | +`generateMultiSizes`（按原格式缩放三档，返回 sizes JSON）；addAdminUpload 调用 |
| `web/front/UpLoadController`（编辑器通道） | 上传后登记 fly_images 行 + 多尺寸（修编辑器上传不入库的既有缺口） |
| `ModelDataDao.findImageUrls` | SELECT 加 sizes |
| `ModelDataService.expandAttachments` | `{field}Srcset` 生成 |
| 前台模板 | detail-images/detail-products 缩略图加 srcset（示例） |

## 2. Q2 区块编辑器迭代（V3.1 快赢 + 路线）

### 2.1 V3.1 快赢项（本期实现）

| 项 | 规格 |
|---|---|
| 区块复制 | 区块行「复制」按钮：复制标题（加"副本"）/类型/引用/状态，排序插到原区块之后（后续区块 sort 顺延） |
| 碎片库搜索增强 | 碎片下拉支持按标题/键搜索（已有）+ 显示碎片类型标记 |
| 预览抽屉增强 | 实时预览抽屉标题带区域名与区块数；变更刷新时保留滚动位置（同一 iframe 不重建，仅替换 srcdoc） |

### 2.2 后续路线（另立项，不在本期）

- 区块属性扩展：per-block CSS 类名/包装器（需 AreaBlock 加列 + 渲染支持）；
- 模板级区块编辑（FSE 式整站模板可视化）；
- 区块版本历史（随模板版本体系）；
- 拖拽自由画布（定案不做，见主方案 §10）。

## 3. 验收标准

- **Q1**：① 管理端直传 PNG/JPG → fly_images.sizes 生成 1–3 档（原图小于 150w 时只有原图档）；② 编辑已有内容，图片 `{field}Srcset` 含多档且按宽升序；③ 无 sizes 的旧行 srcset 回退原图；④ 前台商品/图片详情模板 img 带 srcset 属性；⑤ PNG 透明度不丢（生成档仍为 png）；
- **Q2**：区块复制后新行出现在原区块之后、前台输出顺序正确；
- 回归：`mvn compile`、`vue-tsc`、probe_mall 21/21、probe_x 24/24。
