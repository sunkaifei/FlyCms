## 2. 已生成模型 vs 参考模块：逐列对比

「参考模块」= 存量独立内容模块的表结构（它们就是"用自定义模型该生产出什么"的验收基准）。
「固有列」= 每个 `fly_cmodel_*` 都自动具备的列：`id / short_url / user_id / category_id / title / content / keywords / description / thumbnail / recommend / count_view / count_comment / status / create_time / update_time / publish_time`。

### 2.1 `articles` 模型（16 行数据）→ 对标 `fly_article`

| `fly_article` 列 | `articles` 模型现状 | 结论 |
|---|---|---|
| `id`/`short_url`/`user_id`/`title`/`content`/`keywords`/`description`/`style`/`color`/`recommend`/`status`/`create_time`/`update_time`/`publish_time` | `style`/`color` 无对应字段 | ✅ 已补（2026-09-29）：`style`(radio)、`color`(color 类型，优于方案的 input) |
| 分类（`fly_article_category_merge`） | 固有列 `category_id` + `fly_model_category`（支持 `father_id` 树） | ✅ 已覆盖 |
| `author`（存量模块是 `user_id`） | 模型字段 `author`（`input`，纯文本） | ⚠️ 纯文本，无法关联作者实体 → E1 已可用，建模时用 relate 字段 |
| 标签 | 模型字段 `tags`（`input`，逗号文本） | ⚠️ **无标签体系**（不可聚合、无标签页） → 需平台级标签表 |
| 评论 `fly_article_comment` | 仅固有列 `count_comment` | ⚠️ **Count 有、评论本体无** → 需 E4 |

### 2.2 `downloads` 模型（2 行）→ 对标 `fly_share` + 下载场景

| `fly_share` 列 | `downloads` 模型 | 结论 |
|---|---|---|
| `id`/`short_url`/`title`/`content`/`user_id`/`recommend`/`status`/`create_time`/`update_time` | 固有列 | ✅ |
| `needmoney` smallint（下载需积分） | ✅ 已补 `needmoney`(number)（积分核扣链路属交易系统，后置） |
| `downloads` text（附件包） | 模型字段 `file`（`file` 类型，单附件） | ⚠️ 旧是**多附件 text**，新是**单附件 id** → 多附件用 `files` 补 |
| `hide` tinyint(2) | ✅ 已补 `hide`(radio) 与 `attachment_pack`(files 多附件包) |
| — | `file_size`/`run_env`(textarea)/`demo_url`/`os_require`/`auth`/`language`/`score` | ✅ 下载场景已在模型侧扩展；`run_env` 为 text 型，已被 G11 排除出列表投影 |

### 2.3 `images` 模型（0 行）→ 对标 `fly_images` 图组场景

| 参考列 | `images` 模型 | 结论 |
|---|---|---|
| — | `images`(images)/`shoot_time`(datetime)/`location`(region)/`camera`(input)/`author`(input) | ✅ 图组场景已覆盖 |
| `img_url`/`img_name`/`file_size`/`img_width`/`img_height` | — | ❌ 属**附件平台层**（`fly_images`），不应下放给模型（同 D11 逻辑） |

### 2.4 尚未生产的模块（0 个模型）→ 每个都能用自定义模型建出来

| 参考模块 | 参考表 | 引擎缺口 | 能否现在生产 |
|---|---|---|---|

| 问答 `questions` | `fly_question`(0 行) | 无 | ✅ 可建 |

| 链接 `links` | `fly_links`(0 行) | **E3 URL 型图片**（`link_logo`） | ✅ E3 已具备 |

## 3. 引擎缺口清单（E1–E10）与生产机制

> 原则：**缺口一律通过"给自定义模型加机制"来补，不为某个模块单开 Java 模块。**

| # | 缺口 | 影响模块 | 生产机制（怎么补） | 优先级 |
|---|---|---|---|---|
| **E1** | **关联引用**（单值 / 多值） | `answers→questions`、`products→brands`、`courses→teachers`、`articles→authors` | 新增 `FieldTypeEnum.RELATE`(bigint) / `RELATES`(json)；`fly_model_field` 增列 `relate_model`（目标模型 code）；写入时校验目标存在且 `status=1`；读取时由 Service 展开为 `{field}Obj` / `{field}List`（模板零二次查询） | **P1 ✅ 已落地并验收（2026-09-28，探针 11/11 PASS）** |
| **E2** | **自关联 / 树形内容** | `answers.parent_id`（回复的回复）、多级内容 | 新增可选固有列 `parent_id`（模型级开关 `enable_tree`），或在字段层允许 `RELATE` 指向**本模型**（`relate_model = 自身 code`）→ **推荐后者**：不新增固有列，一套机制复用 | P2 |
| **E3** | **URL 型图片/文件字段** | `topics.topic_image`、`links.link_logo`、存量迁移（§10.3 的通用坑） | 新增 `FieldTypeEnum.IMAGE_URL` / `FILE_URL`（varchar(500)，**直存 URL 不走 fly_images 引用计数**）；后台控件 = 输入框 + 即时预览；前台模板与 `image` 同构（`${item.xxxUrl}` 直接可用） | **P1 ✅ 已落地并验收（2026-09-28，探针 11/11 PASS）** |
| **E4** | **平台级评论**（D11） | articles / shares / questions / downloads 等**所有**内容模块 | 建 `fly_comment`（`target_type` 模型 code + `target_id` + `user_id` + `content` + `status` + `create_time`），审核/敏感词/通知统一；模型侧只保留"是否开启评论"开关与 `count_comment` 冗余列；前台标签 `fly_comment_list` / `fly_comment_form` | **P1** |
| **E5** | **JSON 结构化字段** | 商品规格参数、房产参数、SKU | ✅ **由 P1 结构层覆盖**：`group`（JSON 对象+子字段 schema 校验）与 `repeater`（JSON 数组）即为"键值对编辑器"的强 schema 版，读侧结构化展开——不再单设自由 JSON 类型 | **P2 ✅** |
| **E6** | **计算列（公式）** | 折扣价 = 原价×折扣、总价 = 单价×数量 | `fly_model_field` 增列 `formula`（表达式），读取时计算**不落库**。**未做（P3）**——ROLLUP 已覆盖跨行聚合，行内公式待真实场景驱动 | P3 |
| **E7** | **内容版本 / 草稿 / 回滚**（= G12） | 所有内容 | ✅ **已落地（2026-09-29）**：`fly_content_version`（target_model+target_id+version），新建/更新/状态切换/恢复全程快照，恢复=另存新版本历史不丢；`version/list`+`version/restore` API + 后台「版本」抽屉 | **P2 ✅** |
| **E8** | **时间窗过滤** | `announcements` 生效期 | ✅ **已落地（2026-09-29）**：`selectPage` 增 `timeField+timeFrom+timeTo`（白名单=固有时间列+本模型 date/datetime 字段，非法格式/非法列静默忽略）；`fly_page_model` 标签与后台列表均支持，探针 6/6 | **P3 ✅** |
| **E9** | **模型级特性开关** | 所有模型 | 🟡 **部分落地**：`use_content`/`use_seo`（表单页签开关）已上线；`enable_comment`/`enable_version` 等 per-model 开关未做——评论/版本已是平台能力（全模型可用），per-model 粒度按真实需求后置 | P2 🟡 |
| **E10** | **"重新生成骨架"按钮 + 标签注释块**（D13 收尾 = G20） | 所有模型 | ✅ **已落地（2026-09-29）**：`POST /api/system/model/regenTemplates/{id}`（复用模型更新权限）强制覆盖 list/detail 并注入 `tagCheatSheet` 注释块（可用标签 + 逐字段取值写法，按类型给出 image/relate/user/group 等展开式样）；模型列表「重新生成模板」按钮带覆盖确认 | **P3 ✅** |

### 3.1 E1 实现规格（本批次落地）

```java
// bug 1: FieldTypeEnum 新增
RELATE("relate", "bigint(20) unsigned", null),    // 单值：存目标模型内容的 id
RELATES("relates", "json", null),                  // 多值：存 id 数组 JSON
```

```sql
-- fly_model_field 增列（承载关联目标）
ALTER TABLE `fly_model_field`
  ADD COLUMN `relate_model` varchar(32) DEFAULT NULL
  COMMENT 'RELATE/RELATES 字段的目标模型 code；为空表示关联本模型（自关联树）';
```

**四条链路都要改**：① 元数据读写（`ModelFieldService` + `ModelFieldDao.xml`）；② 写入校验（`ModelDataService.buildDynamicValues`：目标 id 必须存在且 `status=1`）；③ 读取展开（`expandAttachments` 同构 → `expandReferences`，输出 `{field}Obj` / `{field}List`）；④ 前端控件（`RelatedPicker`，数据源 `GET /api/system/modelData/list/{targetModelId}`）。

### 3.2 E3 实现规格（本批次落地）

```java
IMAGE_URL("image_url", "varchar(500)", null),      // 直存 URL 的图（不走引用计数）
FILE_URL("file_url", "varchar(500)", null),        // 直存 URL 的附件
```

**与 `image`/`file` 的区别**：`image`/`file` 存 `fly_images.id` 并维护 `info_count` 引用计数（受"附件库"生命周期管理）；`*_url` 存裸 URL，**不参与引用计数**——这正是存量表 `topic_image` / `link_logo` 的形态，也是 §10.3 冲突的正解（推荐方案：不反查 id，另存 URL）。

## 5. 实施顺序与验收

```
第 1 批（引擎 P1，本批次）   E1 关联字段 + E3 URL 图片字段        ← 解锁 6+ 个模块的生产
第 2 批（平台能力 P1）       E4 平台评论（fly_comment 多态）      ← 解锁所有内容模块的评论
第 3 批（模型生产）          §4.1 六个模型 → §4.2/§4.3 八个模型    ← 真正的"用自定义模型生产出来"
第 4 批（编辑体验）          E7 版本 / E9 特性开关 / E10 骨架注释
第 5 批（收敛下线）          P10/P11：切前台路由 + Nginx 301 + 删旧控制器
```
