> ② 主流 CMS 在字段控件上给了管理员哪些配置项（对标）；
> ③ FlyCms 怎么补：存储、后端、前端逐文件改造设计；
> ④ 分几期做、每期怎么验收。
> 上游文档：《自定义模型引擎对标调研与万能建模完善方案》（类型层 P0–P2）、《自定义模型系统开发手册》（§5 后端 / §6 前端）、《主流CMS对标与全项目优化开发方案》§13（万能标签三层）。
> 触发：用户实测点评——附件控件是裸 ID 输入框、单图不是头像式、时间字段没有格式/范围、多行文本行数写死。

| 关系 | relate / relates / m2a / user / category |

## 2. 对标

| 系统 | 字段控件层的做法 | 值得抄的点 | 不抄的部分 |
|---|---|---|---|
| **WP + ACF**（字段配置的事实标准） | 每个字段一堆控件级设置：image 有「预览尺寸 / 返回格式(array/url/id)」；date_time_picker 有「显示格式 / 返回格式 / 周首日」；textarea 有「行数 / 换行转 br」；number 有 min/max/step/前后缀；select 可选 checkbox/radio/select 三种形态 | ① 控件配置**按类型出现**（image 才有预览尺寸）；② 值格式与显示格式分离（存储恒定、显示可变） | 返回格式多态（array/url/id 切换）——FlyCms 存储语义由类型定死，不引入同字段多存储 |
| **帝国 CMS** | 字段「输入表单替换 HTML」——管理员可整段替换录入控件；图片字段自动缩图函数、附件按栏目归档 | 图片字段"上传即处理"（缩图/水印）的意识 | **替换 HTML 明确不做**：自由度=维护与安全噩梦（XSS/升级失配），见 §8 |
| **DedeCMS** | 字段类型即控件（图片=带上传按钮的表单、附件=下载框），per-field「表单提示文字/默认值」 | 单图字段的"表单即上传"直觉 | 字段类型与存储耦合过死，扩展全靠改源码 |
| **PHPCMS v9** | 字段模型分「字段类型 + 表单参数」两组配置，按类型动态出表单参数面板 | 「控件设置」面板按类型动态渲染的组织方式（本项目 field-modal.vue 已有同构先例：maxlength 仅 input、选项仅 select 族） | — |
| **迅睿/XunRuiCMS** | 字段与控件类解耦，每字段可选控件类 + options JSON | **与本文方案同构**（类型定存储 + conf 定控件），国内验证过的路线 | 控件类体系过重（上百个类），FlyCms 用 JSON 配置即可 |
| **Directus** | **Interface（录入界面）与 Field（存储）彻底解耦**：每个 interface 带 options JSON、display 与 interface 分离、条件显隐作用在 interface 上 | interface options 的白名单 schema 思路（本方案 widget_conf 的直接参照）；条件显隐本项目已有（visible_when） | interface 可自由装插件——本项目不引入插件机制，以枚举白名单为界 |
| **Strapi / Payload** | 按类型自动选 widget，定制靠写代码（custom input 组件） | —— | 定制靠代码不适合"零代码建站"定位 |

**对标结论**：主流共识是「**字段类型定存储，控件配置定录入**」。FlyCms 采用轻量版 Directus/迅睿路线：不加一堆碎列（防列爆炸），`fly_model_field` 加**一列 `widget_conf`（JSON）**，每类型一份**白名单 schema** 校验；控件交互形态的重写集中在附件族（W1，用户点名）与时间/文本族（W2，用户点名）。

## 3. 总体设计

### 3.1 存储：只加一列

```sql
-- sql/migrations/2026-10-xx-field-widget-conf.sql（W1 落地时出）
ALTER TABLE `fly_model_field`
  ADD COLUMN `widget_conf` text COMMENT '控件配置 JSON（白名单 schema，NULL=全默认）' AFTER `options`;
```

基线 `sql/flycms_20260928_093335.sql` 同步加列。`widget_conf` 为 NULL 或空 JSON 时行为与现状**逐像素一致**（存量模型零影响）。

### 3.2 配置白名单（后端权威，前端同清单渲染设置面板）

新增 `FieldWidgetConfUtil`：`Map<fieldType, 允许键 → 取值域>`，`check(fieldType, json)` 做三道校验——合法 JSON、键在白名单内、值在取值域内；非法即 `DataVo.failure` 拒绝保存（防垃圾 JSON 进库，坑同 V1 options 裸串教训）。schema 定义见 §4 各类型表格的「配置项」列，后端与 field-modal 设置面板**同源**（前端以注释标注与后端同步）。

### 3.3 下发与消费

`formMeta`（`GET /api/system/modelData/formMeta/{modelId}`）每字段输出 `widgetConf`（已解析 Map；G14 字段权限剔除逻辑不变——widgetConf 属字段元数据，随字段走）。`DynamicFieldInput` 增加一个 `conf` prop 消费；**发布表单（form-modal）与前台投稿页（submit）走同一组件链路，自动生效，零额外改造**。

### 3.4 上传通道补缺（W1 前置，无此则附件控件重写是空谈）

新增管理端上传端点（复用既有安全设施 `UploadSafeUtil` / `ImageUtils`，落 `fly_images`，`img_delete=0`，引用计数语义与附件库一致）：

```
POST /api/system/images/upload   # multipart file；requirePermission("/api/system/images/*")
# 返回 DataVo.success("上传成功", {id, imgUrl})
GET  /api/system/images/batch?ids=1,2,3   # 返回 [{id, imgUrl, imgName}]，供控件回显（修 W-P3）
```

权限：`/api/system/images/*` 尾星号通配节点已存在且已授权（附件库管理页在用），**无需新增权限行**。

### 3.5 「单图还是多图」的选型定案

**不合并 image/images 两个类型**——存储本质不同（`bigint` 单 id vs `json` id 数组），合并会破坏存量数据与全部读侧展开（`{f}Url` / `{f}Urls`）。定案：

- **新建字段时选类型即选形态**（image=单图 / images=多图），字段编辑器在类型下拉旁给一句引导说明（用户诉求的"选择单图还是多图"落在这里）；
- 控件交互形态按类型分化：image=头像式（W1 重写），images=网格式多图（W1 重写）；
- 字段编辑器提供 image↔images 的**带警告的类型切换引导**（创建后类型不可改的既有约束不变；提示文案指向"新建同名字段+数据迁移"的手工路径，本期不做自动迁移）。

## 4. 分类型增强设计

### 4.1 附件族（W1，用户点名，含 bug 修复）

**image 单图 —— 头像式控件（ImageSingleWidget）**

| 项 | 设计 |
|---|---|
| 配置项 | `shape`：`square`(默认 96px 圆角方形) / `circle`(圆形，头像场景)；`maxSize`：提示性大小上限 MB（超限前端拦截） |
| 空态 | 虚线框占位（图标+"点击上传"），点击弹「添加图片」三 Tab 弹层：**上传**（直传 §3.4 端点，支持粘贴/拖拽）｜**附件库**（复用现有分页选择器，选完即回）｜**外链 URL**（直填，仅 image_url 语义场景提示改用 image_url 类型） |
| 有值态 | 大缩略图 + 悬停遮罩两按钮（更换 / 删除）；点击图可全屏预览 |
| 存储 | 不变：`fly_images.id`（bigint） |
| 顺带修复 | W-P3 回显（打开表单时按 id 批量拉 url 映射）；W-P2（裸 ID 输入框彻底移除） |

**file 单文件 —— 文件卡片控件（FileSingleWidget）**

文件图标 + 文件名 + 大小 + 「更换 / 删除」；空态同三 Tab 弹层（无预览，上传后显示原始文件名）。存储不变。

**images / files 多值 —— 网格画廊控件（GalleryWidget）**

| 项 | 设计 |
|---|---|
| 配置项 | `maxCount`：1–50（默认 20，超出拒绝并 toast）；`sortMode`：`drag`(默认) / `fixed` |
| 控件 | 缩略图网格（88px）+ 尾部「+」块（同三 Tab 弹层，上传支持多选批量直传与进度条）；**拖拽排序**（HTML5 原生 DnD，落库按新顺序写 JSON，免新依赖）；每图悬停删除角标 |
| 存储 | 不变：json id 数组；顺序即数组序（前台 `{f}Urls` 顺序随之） |

### 4.2 时间族（W1，用户点名）

| 类型 | 配置项 | 控件行为 | 存储 |
|---|---|---|---|
| date | `format`：`YYYY-MM-DD`(默认) / `YYYY-MM` / `YYYY` | DatePicker 精度联动（月/年选择器）；value-format 跟随配置 | 不变（date） |
| datetime | `format`：`YYYY-MM-DD HH:mm`(默认) / `YYYY-MM-DD HH:mm:ss` | DatePicker showTime 精度联动（分/秒） | 不变（datetime） |
| **date_range**（新类型） | ——（无配置，形态即语义） | RangePicker；值 `["2026-10-01","2026-10-15"]` | **json 列**（FieldTypeEnum 新增 `date_range("date_range","json")`） |
| **datetime_range**（新类型） | —— | RangePicker showTime | json（同上） |

设计定案：**范围做成独立类型而非 date 的控件开关**——范围值的存储（json 数组）、列表筛选语义（重叠命中：`start <= 存储end AND end >= 存储start`）、前台展示（起~止）都与其他情况不同，同类型开关会制造三义性。`selectPage` 的 filters 白名单放行这两个类型的重叠查询；读侧展开 `{f}Start/{f}End` 两键便于模板直出。

### 4.3 文本族（W1 多行文本 + W2 单行/数值）

| 类型 | 配置项 | 控件行为 |
|---|---|---|
| **textarea**（用户点名） | `rows`：1–30（默认 3）；`autoSize`：bool（开则忽略 rows，{minRows:2,maxRows:rows}）；`showCount`：bool（配 maxlength 显示 x/N） | rows 接通配置；maxlength 列接通（此前只有 input 接了） |
| input | `addonBefore` / `addonAfter`：文本前/后缀（如 `https://`、`.com`） | Input addon（纯装饰，不入库） |
| number / decimal | `addonAfter`：单位（如 `元`、`kg`）；decimal 加 `step`（默认 0.01） | InputNumber addon + step |
| slug | `prefix`：展示前缀（只读装饰） | 前缀 + 输入框 |
| editor | `height`：240–1200（默认 360）；`mode`：`full`(默认) / `simple` | 编辑器高度与工具栏档位 |

### 4.4 选项与其他（W2）

| 类型 | 配置项 | 控件行为 |
|---|---|---|
| select / radio | `layout`：`select`(select 默认) / `row`(横排 radio) / `column`(竖排 radio) / `button`(标签组) | 选项少时横排/标签组录入更快（对标 Dede radio 表单与 ACF stylized ui）；候选项来源逻辑不变（字典>options） |
| checkbox | `layout`：`checkbox`(默认) / `button`(标签组) | 同上 |
| switch | `checkedText` / `unCheckedText`：激活/关闭文案（如"显示/隐藏"） | Switch 文案 |
| rating | `count`：1–10（默认 5）；`allowHalf`：bool | 星数与半星 |
| color | `palette`：JSON 色值数组（如 `["#1677ff","#f5222d",…]`） | 色板快捷块 + 现有取色器 |

### 4.5 配置项总表（速查）

| 类型 | widget_conf 允许键 |
|---|---|
| image | shape, maxSize |
| images / files | maxCount, sortMode |
| date | format |
| datetime | format |
| textarea | rows, autoSize, showCount |
| input | addonBefore, addonAfter |
| number / decimal | addonAfter（decimal 加 step） |

## 6. 兼容性与权限

- **存量零影响**：widget_conf NULL → 全默认 = 现状；不加白名单外的行为；存储列不动（仅加列），前台模板取值（`{f}`/`{f}Url`/`{f}Urls`/`{f}Obj`…）语义不变；
- **image/images 不合并**（§3.5）；date_range/datetime_range 是新增类型，不影响存量 date/datetime；
- **权限**：新上传端点挂既有 `/api/system/images/*` 通配节点，无需新权限行与授权动作；前台投稿页与后台表单同链路，无需前台权限变更；
- **G14 字段权限**：widgetConf 随字段元数据走，被锁字段整字段剔除时一并消失，无新增口径。

## 8. 不做清单

- **帝国式「输入表单替换 HTML」**：自由度即攻击面（XSS）与升级失配；Directus 式白名单 conf 是更优解，本项目以 FieldWidgetConfUtil schema 为界；
- **可视化控件构建器**（拖拽设计录入控件）：字段级 32 类型 × 有限配置项，面板已够；
- **image/images 类型合并或自动迁移**：存储本质不同，切换走"新建字段+手工迁移"引导；
- **分片/断点续传**：小站场景收益低，直传上限由 UploadSafeUtil 既有约束兜底；
- **date_range 作为搜索页独立控件**：列表筛选重叠查询已覆盖，前台搜索表单另议。
