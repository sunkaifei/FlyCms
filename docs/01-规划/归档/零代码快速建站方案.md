## 2. 架构判断：不造拖拽编辑器，造"站点预设包"

零代码平台通常靠**可视化拖拽编辑器**达成易用性——那是大工程且与本系统"模型驱动"的基因冲突。
本系统实现同一目标（快速建站）的天然路径是 **"配置打包复用"**：

> 把"某类站点的全部组装动作"（模型定义/字段/分类/栏目/导航/模板文件/设置项/示例内容）
> 打包成一个**站点预设（Site Preset）**；建站者选类型 → 向导一键应用 → 得到一个**能跑的完整站**，
> 之后只改 logo/站名/文案/配色。

零件已全部存在（只差串联）：
- **G20 模型导入导出**：模型/字段/分类按 code/fieldName/名称幂等对齐导入 ✅
- **骨架模板自动生成**：后端有能力写模板文件到当前皮肤（E10 regenerateDefaultTemplates 同机制）✅
- **建模型自动出后台菜单**（syncModelMenuNodesOnSave）✅
- **导航/栏目均有后台 API**（fly_guide / fly_channel）✅
- **设计令牌**（theme.json→CSS 变量，G19）——改配色不用碰模板 ✅

## 3. 设计

### 3.1 站点预设包（Site Preset）格式

一个预设 = 一个 JSON 清单 + 内嵌模板文件，全部数据化（可导入导出、可随发行版内置、可社区分享）：

```json
{
  "preset": { "code": "qa", "name": "问答网站", "version": 1, "icon": "lucide:messages-square",
              "description": "类似百度知道：提问/回答/采纳，内容前台生成" },
  "groups":  [ { "name": "问答", "code": "qa", "icon": "..." } ],
  "models":  [ /* G20 既有格式：模型+字段+分类（questions/answers…） */ ],
  "settings": [ { "key": "fly_article_audit", "value": "1" } ],
  "channels": [ { "name": "问答", "dir": "questions", "model": "questions",
                  "channelType": 0, "listTemplate": "list-questions.html" },
                { "name": "关于我们", "dir": "about", "channelType": 1, "pageContent": "…" } ],
  "guides":  [ { "name": "问答", "type": 1, "ref": "channel:questions" },
               { "name": "关于我们", "type": 1, "ref": "channel:about" } ],
  "templates": [ { "file": "detail-questions.html", "content": "<#-- 模板全文 -->" },
                 { "file": "list-questions.html", "content": "…" },
                 { "file": "submit-questions.html", "content": "…" },
                 { "file": "submit-answers.html", "content": "…" } ],
  "sampleContent": [ /* 可选：示例问题/文章（让建站者看到"长什么样"，可一键清空） */ ]
}
```

### 3.2 应用流程（幂等，可重复应用/升级）

`POST /api/system/preset/apply`（管理员）→ `PresetService.apply(json)`：
1. 分组：按 code 对齐创建/更新（幂等，同 G20 口径）；
2. 模型/字段/分类：委托 `ModelTransferService.importModel`（既有 G20 幂等导入）；
3. 设置项：写 fly_config_web（只写缺失键，不覆盖管理员已改值）；
4. 栏目：按 dir 对齐创建/更新（bind 模型、模板）；
5. 导航：按名称对齐创建（type=栏目引用）；
6. 模板文件：写入当前皮肤目录（**同 E10 机制**；已有同名文件时按 `overwrite` 策略：默认跳过保护管理员改动，向导里可勾选"覆盖"）；
7. 示例内容（可选勾选）：投稿通道语义插入，打 `is_sample` 标记（配套"一键清空示例"）；
8. 返回应用报告（每步 created/updated/skipped）。

**预检**：模型 code / 栏目 dir / 分组 code 冲突时报告并按对齐策略处理，不半途破坏站点。

### 3.3 建站向导（管理员后台，三步）

1. **选类型**：预设卡片墙（问答/博客/图片站/企业官网/分类信息/商城/空白站），每卡注明能力与页面截图；
2. **基本信息**：站名/Logo/配色（写 G19 设计令牌与站点配置）/选主题皮肤；
3. **应用**：一键执行预设 → 跳转前台预览 → 提示"进模型管理调整字段、进模板管理微调页面"。

新装系统首次进入后台时引导进入向导；已建站点可随时再应用其他预设（增量扩展，如给企业官网加"新闻"模块）。

## 6. 不做清单

- **拖拽可视化页面编辑器**：另立大项（本方案用"预设给完整站+模板微调"达成易用性，两者互补不互斥）；
- **SaaS 化**（注册即用/多租户隔离/计费）：产品形态定案为独立部署，不做；
- **预设市场/在线分发**：本期预设随发行版内置（JSON 文件），社区分享机制后置；
- **自动升级迁移**：预设应用是幂等配置对齐，不做站点版本管理。

## 8. 区块化编辑器（排版层，P-4 期）

### 8.1 定位与地基

目标：让"改页面布局"也零代码——鼠标拖区块、点选改属性、实时看效果；不要求自由画布（自由画布另立项）。

**地基已存在（不重造）**：
- 区域编排 V2：`fly_area`（区域，如首页头图区）/ `fly_area_block`（区域内的区块，类型=碎片 key/标签代码/HTML，有排序/启用）；
- 区域管理页 `/system/area`（表格式管理：新增/编辑/排序/预览区域）；
- 前台渲染：模板 `<@fly_area name="home_focus">` 按排序输出启用区块；
- 模板片段库（V5 图案库）+ 碎片（fly_block）：即"区块素材库"。

**V3 增量 = 给区域管理页装上可视化外壳**，四件事：拖拽排序、区块库快速添加、实时预览、页面-区域映射视图。

### 8.2 功能规格

| 能力 | 规格 |
|---|---|
| 拖拽排序 | 区块行 HTML5 拖拽重排，落库 `sort`（顺序即前台输出序）；`fixed` 语义保留（不启用拖拽的区块锁定） |
| 区块库快速添加 | 新增区块弹层改双 Tab：① 素材库——图案库（patterns）+ 碎片（fly_block）列表点选即插入（引用型区块零配置）；② 自定义——手填类型/标题/引用内容 |
| 实时预览 | 编辑区侧栏嵌 iframe 调后台试渲染接口（`GET /api/system/area/preview/{areaId}`，服务端按当前区块序列渲染该区域 HTML 片段，免登录 token 同模板预览机制）；变更即刷新 |
| 页面-区域映射 | 区域列表页首列展示"被哪些模板 include"（扫描模板文本 `fly_area name="…"` 建映射，管理页只读提示），建站者知道改哪里生效在哪个页面 |
| 启用/停用 | 区块行开关即时生效（渲染侧本就按 status 过滤） |

### 8.3 技术要点

- 拖拽：HTML5 DnD（与 W 批次 gallery 同套路），落库逐行 update sort；
- 试渲染：复用模板预览的隔离渲染通道（TemplateCenterService.preview 同源），渲染范围限定 `<@fly_area>` 片段模板，不落盘不缓存（prod 下绕过页面缓存加 no-store）；
- 页面-区域映射：启动时/保存时扫描当前皮肤模板文本正则匹配，结果缓存于内存（模板保存事件失效）；
- 全部为现有页面（/system/area）的增强，无新表。

### 8.4 验收（并入 probe_preset 或独立走查）

① 拖拽换序 → 预览顺序同步；② 从图案库点选添加区块 → 预览出现且前台生效；③ 停用区块 → 预览与前台同步消失；④ 页面映射提示与模板实际 include 一致。

## 9. 实施规格（可执行版）

### 9.1 PresetService（module/preset）

| 方法 | 语义 |
|---|---|
| `listInstalled()` | 扫描 `classpath:presets/*.json` 返回预设卡片（code/name/icon/description/已应用标记） |
| `apply(code, options)` | 幂等应用全流程（§3.2 八步）；options = `{overwriteTemplates:boolean, withSampleContent:boolean}`；返回逐步报告 |
| `clearSample(code)` | 按标记删除该预设插入的示例内容 |

应用顺序与幂等键：分组(code) → 模型/字段/分类(委托 G20 importModel，code/fieldName/名称对齐) → 设置键(key 存在即跳过) → 栏目(dir) → 导航(name) → 模板文件(路径存在默认跳过；overwrite=true 才写) → 示例内容(带 sample 标记键)。

### 9.2 端点（web/api/ApiPresetController，管理端权限）

| 端点 | 语义 |
|---|---|
| GET /api/system/preset/list | 预设卡片 + 应用状态 |
| GET /api/system/preset/detail?code= | 预设清单内容概览（含将创建的对象计数） |
| POST /api/system/preset/apply | body: code / overwriteTemplates / withSampleContent → 逐步报告 |
| POST /api/system/preset/clearSample | 清示例内容 |

权限行 `/api/system/preset/*`（900380）授权超管组；vben 菜单「建站向导」900381（C，/system/preset）。

### 9.3 前端（views/system/preset/index.vue + api/core/preset.ts）

卡片墙 → 选卡弹向导（三步：基本信息/选项勾选[覆盖模板、含示例内容]/确认应用→逐步报告）。首次进后台（模型数为 0 或无已应用预设）顶部横幅引导。
