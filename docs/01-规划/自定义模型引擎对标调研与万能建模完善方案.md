# 自定义模型引擎对标调研与「万能建模」完善方案

> 调研日期：2026-09-28。宗旨（README 已立项）：**自定义模型引擎是本系统核心技术，一切内容模块只由后台在线建模生产（万能系统）**。
> 本文回答两个问题：① 市面上所有自定义模型/内容建模写法各自强在哪；② FlyCms 引擎要补什么，按什么顺序补，才能达到「后台在线建模 = 生产任意程序模块」。
>
> 关联文档：《自定义模型能力缺口与内容模块生产方案》（E1/E3 已验收）、《主流CMS对标与全项目优化开发方案》§9.4（阶段 U 旧模块退役）。

## 1. 调研对象与一句话总评

| 系统 | 建模哲学 | 最值得抄的优点 |
|---|---|---|
| **WordPress + ACF** | 元数据键值 + 字段组挂载 | 30+ 字段类型、**条件显隐（Conditional Logic）**、Repeater/Flexible Content 页面组装、Clone 复用、Local JSON 配置文件化、位置规则（Location Rules） |
| **Strapi 5** | Schema 即代码（schema.json 自动生成） | Content-Type Builder 全在线建模、**Component（可复用字段组）+ Dynamic Zone（自由拼装区块）**、6 型关系、草稿/发布双态、UID(slug) 字段、字段级 Private、**唯一/长度/正则/区间校验内建**、AI 自然语言建模 |
| **Drupal Field API** | FieldType/Widget/Formatter 三插件分离 | 字段类型↔录入控件↔展示格式**解耦**（同一字段多种展示）、cardinality 多值、字段级权限 hook_field_access、实体引用生态 |
| **Directus** | 数据库内省（已有表直接变 API） | 真实 SQL 列存储、**M2A（多对任意）关系**、字段级翻译、Flows 自动化、Lookup/Rollup 聚合、原生 MCP Server |
| **Payload CMS** | 代码优先 TypeScript | **Blocks/Array 字段**（结构化重复子字段）、多态 relationship、版本/草稿内建、字段级 access control 函数 |
| **Sanity** | 文档 + Portable Text | GROQ 查询、数组内嵌对象引用、实时协作 |
| **Contentful** | Entry + Locale | 校验规则完备（unique/regexp/range/in）、迁移脚本化（schema 变更必配迁移） |
| **NocoDB / Airtable** | 智能表格 | **Formula（公式列）、Lookup（跨表取值）、Rollup（跨表聚合）**、多视图（表格/看板/日历/画廊/表单）、Barcode/QR/Geo 等 30+ 类型 |
| **帝国 CMS** | 主表/副表可选 + 微观字段控制 | **自定义字段可进主表**（列表筛选免 join）、字段前后台分别授权、结合项（多字段联合筛选） |
| **PHPCMS / DedeCMS** | 组件化字段 + 全局模型设置 | 字段类型组件化（录入界面自动生成）、**建模后可直接预览录入界面**、主表+副表/独立表双模式 |

**共性结论（所有系统都做、且被证明必要的 10 件事）：**

1. 字段类型分层：基础类型 / 选择类型 / 附件类型 / 关系类型 / 结构类型（组·重复·区块）。
2. 校验内建于字段定义（required / unique / regex / min/max / 枚举白名单），写入时服务端强制。
3. **条件显隐**（某字段根据另一字段值出现/消失）——ACF/Strapi 均为核心卖点。
4. **可复用结构**：Component/Clone/字段组，跨模型复用字段集合。
5. **重复子字段**（Repeater/Array/Blocks），页面组装类内容的刚需。
6. 关系是一等公民：单向起步，逐步 1:N / N:N / 双向 / 多对任意。
7. slug/UID + 唯一约束：URL 友好化的标配。
8. 草稿/发布/版本：编辑安全网。
9. Schema 导入导出（JSON/YAML）：环境迁移与复用。
10. 建模后**即时预览录入界面**，所见即所得地调字段。

## 3. 万能建模补齐路线（按「能不能生产出模块」排序）

### P0 · 写入质量层（✅ 本轮已落地并验收）

- 7 个轻量字段类型：`switch`（开关，tinyint(1)）、`email`、`url`（http/https 校验）、`phone`（1[3-9] 手机号）、`color`（#RGB/#RRGGBB/#RRGGBBAA）、`rating`（1..5，可配区间扩量程）、`slug`（小写字母数字中划线，**常配唯一**，对标 Strapi UID）。
- `fly_model_field` 新增 `is_unique` / `min_value` / `max_value` 三列（迁移：`sql/migrations/2026-09-28-model-field-advanced.sql`，幂等）。
- 写入校验：格式拒绝走 `DataVo.failure` 业务错误；唯一约束查重 `countDuplicate`（列名来自字段元数据白名单，值走 `#{}` 预编译，更新排除自身）。
- 前端：字段弹窗新增 7 类型 + 值唯一 + 最小/最大值（仅 number/decimal/rating 显示）；内容表单新增 Switch/Rate/取色器控件。
- **验收：探针 15/15 PASS（`tools/_tmp_scripts/probe_p0_types.py`，含 6 组负向 + 唯一重复 + 更新排除自身）；e2e PASS 51；audit PASS 16；vue-tsc 通过。**
- ⚠️ 新坑记录：**MySQL 5.7 保留字 `MAXVALUE`**（大小写不敏感），SQL 别名 `AS maxValue` 直接 1064 语法错误，必须写 ``AS `maxValue` ``（`minValue` 不受影响）。

### P1 · 结构表达层（补齐「复杂内容」建模，预计 5–8 人日）

对标 ACF Repeater/Group 与 Strapi Component/Dynamic Zone：

| 项 | 方案 |
|---|---|
| **GROUP 子字段组** | `FieldTypeEnum.GROUP`：JSON 列存对象；子字段定义存 `fly_model_field.parent_id`（字段表自关联），表单递归渲染 |
| **REPEATER 重复行** | 同 GROUP 存储结构 + `multiple=1`；JSON 列存数组，每行按子字段 schema 校验 |
| **条件显隐** | `fly_model_field.visible_when` JSON（`{"field":"probe_switch","op":"eq","value":"1"}`），后端写入跳过隐藏字段校验，前端表单联动显隐 |
| **可复用字段组（Component）** | 与 M 阶段 `fly_block_type` 合流：字段组定义为一种「纯字段区块」，可被多模型挂载 |
| **模型预览录入界面** | PHPCMS 式：建模页加「预览表单」按钮，复用 form-modal 只读渲染 |

### P2 · 关系与聚合层（向 Directus/NocoDB 看齐，预计 6–10 人日）

| 项 | 方案 |
|---|---|
| **关系 6 型** | 现有 relate/relates 已覆盖单向 1:1/N:1；补「双向标注」——目标模型自动生成反向字段（读时 JOIN 反查），无需物理列 |
| **Lookup** | 虚拟字段：读取时按 relate 字段展开目标行指定列（`{field}Obj.title` 已具雏形，做成字段定义可选展示列） |
| **Rollup/统计** | 虚拟字段：COUNT/SUM/AVG 目标模型关联行数或数值列（`fly_model_field.rollup_expr` + 白名单聚合函数） |
| **多对任意（M2A）** | 中间表 `fly_relation(from_model,from_id,to_model,to_id,sort)`，承接「内容可关联任意模型」场景（相关阅读/商品推荐） |

### P3 · 平台能力层（向 Strapi/Directus 看齐，与既有阶段合并执行）

| 项 | 归属 |
|---|---|
| slug → 前台 URL 通道（`/cmodel/{code}/{slug}` + 301） | 与 SEO/路由规划合并 |
| 单页型模型（single type，如「关于我们」只有一条） | `fly_model.kind` 加 `collection/single`，后台菜单与权限差异化 |
| 字段级权限（前台投稿哪些字段会员组可写） | 并入 G14 字段级权限 |
| 模型导入导出 schema-as-code | 已在 N 阶段 G20（model/export+import YAML） |
| 草稿/版本/回滚 | 已在 M 阶段 G12（fly_content_version） |
| 事件钩子（建模变更 → 清缓存/重建索引/webhook） | 已在 N 阶段 G17（Spring 事件扩展点） |
| 多视图（看板/日历/画廊）与公式列 | 低优先级，录入体验成熟后再做 |
| AI 自然语言建模（Strapi AI 式） | 并入 P 阶段 AI 能力（G22） |

## 4. 结论

引擎的「**类型层 + 校验层 + 安全层**」经 P0 批次已达到主流程 CMS 的底线水位；「**结构层**（GROUP/REPEATER/条件显隐）」与「**关系聚合层**（Lookup/Rollup/M2A）」是 remaining 的两大硬缺口，分别对应 P1/P2。**顺序上：P1 直接决定旧模块退役（阶段 U）能否覆盖 share/question 这类带子结构数据的模块，因此 P1 优先于 P2；P3 全部复用既有阶段（M/N/G14/G20/G22），不单独排期。**

每完成一批，回写本文档 §3 状态，并同步 `docs/README.md` 索引。
