## 1. 背景与现状分析

### 1.1 现状痛点

FlyCms 目前每种内容类型都是**一整套独立代码**：article（文章）、share（分享）、question/answer（问答）、topic（话题）、brand（品牌）、job（招聘）——每种内容 = `module/<name>/{model,dao(+XML),service}` + `web/system/XxxAdminController` + `web/front/XxxController` + `views/templates/system/**` 后台页 + `pc_theme` 前台模板。**每新增一种内容类型要复制这套东西一遍**，这正是自定义模型系统要解决的问题：把"内容类型"变成后台可配置的元数据。

已有铺垫：`views/templates/system/model/model_list.html` 存在一个"模型管理"后台页面雏形（列表列：排序/模型ID/模型名称/标识/状态；按钮：添加模型/复制模型），但**没有任何 Java 代码引用它**——本手册的任务就是把它背后的系统真正建起来。

### 1.2 技术栈与代码组织（开发必须遵守的既有约定）

| 项 | 内容 |
|---|---|
| 框架 | Spring Boot 4.1.1（parent），Java 24，Maven 单模块，Jetty |
| ORM | MyBatis 4.1 starter；**Dao 接口与 XML 同目录**：`module/<name>/dao/XxxDao.java + XxxDao.xml`（pom 已配置打包 java 目录下所有资源） |

### 1.3 fly_article 表结构特点（决定新模型的表设计风格）

`fly_article` 是**单表设计**：`id` + `short_url`（varchar(10)）联合主键，`title/content/keywords/description` 都在主表，`status`（0未审 1正常 2未通过 3删除），`recommend` 排序权重。分类 `fly_article_category`（father_id 树形，MyISAM）+ `fly_article_category_merge`（文章-分类关联）。**无多语言、无站点维度、无分表**。自定义模型表沿用同样的单表 + 联合主键风格，保持全库一致。

## 3. 架构决策（定案）

### 决策一：每模型一张物理表，字段直接做列（帝国CMS式）

`fly_cmodel_{modelId}` 一张主表，自定义字段 = 真实列（可索引），多值字段（图组/多选）用 JSON 列。对比 EAV / 纯 JSON 方案的论证：建站 CMS 的列表查询、排序、筛选需要真实索引，结论同 DedeCMS/PHPCMS。

### 决策二：单表单语言，不做 values 表

FlyCms 是单站点、单语言系统（fly_article 即单表含 content），新模型表**直接含 title/content/keywords/description 等内容列**，无需 MxxSaas 方案中的多语言 values 表和 site_id 隔离。整体复杂度比 MxxSaas 方案低一个量级。

### 决策三：现有内容类型保持不动，自定义模型并行新增

与"重建"路线相反——article/share/question/topic 各自有独立业务流（问答的 answer/votes、分享的 order/交易），强行统一为模型风险大收益小。第一期自定义模型只服务**新增内容类型**场景（图片模型、下载模型、产品模型），与现有模块共存。第二期（可选）再评估把 article 迁移为 `is_system=1` 的内置模型。

### 决策四：管理后台前端采用 vue-vben-admin（SPA），新旧并行、分批迁移

后台前端基座确定为 **vue-vben-admin v5**（Vue3 + Vite + TypeScript + pnpm monorepo，文档 doc.vben.pro）。FlyCms 现有后台是 FreeMarker HTML 多页应用（jQuery），登录是"表单 + redirect"页面流，无法直接承载 SPA——因此：

- 本项目范围（模型系统全部页面 + 登录/菜单/权限骨架）在 **vben 内实现**；后端为其新增一组**纯 JSON 接口**（认证 / 动态菜单 / 权限码 / 模型系统，见 5.6 节）。
- **存量模块**（article/question/share 等对应的后台页面）暂保留现有 HTML 后台，作为过渡期并行入口，后续按模块逐步迁入 vben，迁完一个下线一个；`system/model/model_list.html` 占位页由 vben 页面取代，不再激活。
- 登录鉴权桥接：vben 走 token（Caffeine 存储 + `Authorization: Bearer` 头），存量页面继续走 Session，`AdminInterceptor` 双轨兼容（见 5.6 节）。
- 前台站不受影响，继续 FreeMarker SSR。

### 决策五：搜索走 Solr（项目现状），缓存走 Caffeine

内容新增/修改/删除后同步 Solr（沿用 `SolrService`）；模型元数据、主题信息用 Caffeine 缓存。不引入新中间件。

## 4. 数据库设计

### 4.1 模型定义表 `fly_model`

```sql
CREATE TABLE `fly_model` (
  `id`           bigint(20) unsigned NOT NULL COMMENT '雪花ID',
  `name`         varchar(64)  NOT NULL COMMENT '模型名称，如：下载模型',
  `code`         varchar(32)  NOT NULL COMMENT '模型标识（路由/模板目录用），如 downloads',
  `title_label`  varchar(32)  NOT NULL DEFAULT '标题' COMMENT '标题字段显示名',
  `is_system`    tinyint(1)   NOT NULL DEFAULT 0 COMMENT '1内置模型禁删禁改code',
  `list_template` varchar(100) DEFAULT NULL COMMENT '列表页模板（pc_theme下相对路径，空=/{code}/list.html）',
  `detail_template` varchar(100) DEFAULT NULL COMMENT '详情页模板（空=/{code}/detail.html）',
  `icon`         varchar(64)  DEFAULT NULL COMMENT '后台图标(fa类名)',
  `description`  varchar(255) DEFAULT NULL,
  `sort`         int(10)      NOT NULL DEFAULT 0,
  `status`       tinyint(2)   NOT NULL DEFAULT 1 COMMENT '0禁用 1启用',
  `create_time`  datetime DEFAULT NULL,
  `update_time`  datetime DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code` (`code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容模型定义';
```

### 4.2 字段定义表 `fly_model_field`

```sql
CREATE TABLE `fly_model_field` (

  `is_search`     tinyint(1)   NOT NULL DEFAULT 0 COMMENT '同步Solr',
  `is_filter`     tinyint(1)   NOT NULL DEFAULT 0 COMMENT '后台列表筛选条件',
  `regex`         varchar(255) DEFAULT NULL,
```

### 4.3 动态生成的模型数据表（由 ModelTableService 拼装）

固定列与 `fly_article` 风格对齐（含联合主键、short_url、审核状态），自定义字段列按字段定义追加：

```sql
CREATE TABLE IF NOT EXISTS `fly_cmodel_${modelId}` (
  `id` bigint(20) unsigned NOT NULL COMMENT '雪花ID',
  `short_url` varchar(10) NOT NULL COMMENT '短链接（沿用fly_article的10位风格）',
  `user_id` bigint(20) unsigned DEFAULT NULL COMMENT '发布用户',
  `category_id` bigint(20) DEFAULT '0' COMMENT '分类id(fly_model_category或各业务分类)',
  `title` varchar(250) DEFAULT NULL COMMENT '标题',
  `content` longtext COMMENT '正文(editor字段通道)',
  `keywords` varchar(255) DEFAULT NULL,
  `description` varchar(255) DEFAULT NULL,
  `thumbnail` bigint(20) unsigned DEFAULT NULL COMMENT '封面图(fly_images.id)',
  `recommend` int(5) DEFAULT '0' COMMENT '推荐权重，越大越靠前',
  `count_view` int(11) NOT NULL DEFAULT '0' COMMENT '浏览数',
  `count_comment` int(11) NOT NULL DEFAULT '0' COMMENT '评论数',
  `status` tinyint(2) DEFAULT '0' COMMENT '0未审核 1正常 2未通过 3删除（与fly_article一致）',
  `create_time` datetime DEFAULT NULL,
  `update_time` datetime DEFAULT NULL,
  PRIMARY KEY (`id`,`short_url`),
  KEY `idx_category` (`category_id`,`status`),
  KEY `idx_short_url` (`short_url`),
  KEY `idx_user` (`user_id`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='自定义模型数据表';

-- 字段变更（唯一两条 ALTER 模板）
ALTER TABLE `fly_cmodel_${modelId}` ADD COLUMN `{$fieldName}` {$columnType} COMMENT '{$label}' DEFAULT NULL;
ALTER TABLE `fly_cmodel_${modelId}` DROP COLUMN `{$fieldName}`;
```

> `editor` 类型字段不建独立列，统一走 `content` 通道（FlyCms 一文一正文）；封面统一走 `thumbnail`（单图字段的值也存 fly_images.id）。`title/keywords/description` 是模型固有列，字段定义表里不重复定义。

### 4.4 模型分类表（可选，第一期建议直接建）

图片/下载模型通常需要自己的分类。复用 article 的树形结构建一张通用表（`model_id` 维度），避免给每张模型表各建一张分类表：

```sql
CREATE TABLE `fly_model_category` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `model_id` bigint(20) unsigned NOT NULL,
  `father_id` bigint(20) DEFAULT '0' COMMENT '上级类目，顶级为0',
  `name` varchar(50) DEFAULT NULL,
  `keywords` varchar(255) DEFAULT NULL,
  `description` varchar(255) DEFAULT NULL,
  `sort` int(10) DEFAULT '0',
  `status` tinyint(2) DEFAULT '1',
  PRIMARY KEY (`id`),
  KEY `idx_model_father` (`model_id`,`father_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='模型通用分类';
```

### 5.2 FieldTypeEnum 与 SQL 安全工具

```java
package com.flycms.module.model.enums;

/** 字段类型 → MySQL 列定义的唯一合法映射 */
public enum FieldTypeEnum {
    INPUT("input", "varchar(%d)", 255),
    TEXTAREA("textarea", "text", null),
    EDITOR("editor", null, null),           // 不建列，走主表 content 通道
    NUMBER("number", "bigint(20)", null),
    DECIMAL("decimal", "decimal(18,2)", null),
    DATE("date", "date", null),
    DATETIME("datetime", "datetime", null),
    SELECT("select", "varchar(64)", null),
    RADIO("radio", "varchar(64)", null),
    CHECKBOX("checkbox", "json", null),
    IMAGE("image", "bigint(20) unsigned", null),   // 存 fly_images.id
    IMAGES("images", "json", null),                // fly_images.id 数组
    FILE("file", "bigint(20) unsigned", null),
    FILES("files", "json", null),
    REGION("region", "varchar(64)", null);         // 可用 fly_areas 地区数据

    private final String code; private final String ddl; private final Integer defaultLength;
    // 构造器/getter 略

    /** 列类型只能由这里推导产生，禁止接收前端传入的类型串 */
    public String resolveColumnType(Integer maxlength) {
        if (ddl == null) return null;
        return ddl.contains("%d") ? String.format(ddl, maxlength == null ? defaultLength : Math.min(maxlength, 4000)) : ddl;
    }
}
```

新增 `core/utils/SqlSafeUtil.java`（项目没有 SQL 白名单工具，必须新建）：

```java
public final class SqlSafeUtil {
    private static final Pattern SAFE_NAME = Pattern.compile("^[a-z][a-z0-9_]{0,63}$");
    private static final Set<String> RESERVED = Set.of("order","group","desc","asc","select","insert",
            "update","delete","where","index","key","primary","table","values","limit");

    /** 字段名白名单 + 反引号包裹；非法直接抛 IllegalArgumentException */
    public static String safeColumnName(String name);
    /** 数字参数（modelId）拼接前强校验 */
    public static String safeNumber(Object v);
    /** 模型标识校验 ^[a-z][a-z0-9_]{1,31}$（用于路由与模板目录） */
    public static String safeModelCode(String code);
}
```

### 5.3 ModelTableService（动态 DDL，项目全新能力）

```java
@Service
public class ModelTableService {
    @Autowired private ModelDataDao modelDataDao;      // DDL 语句放 dao XML 的 <update> 里
    @Autowired private ModelFieldService modelFieldService;

    /** 新建模型后调用：建数据表 + 按字段定义生成列。调用方放在元数据保存成功之后 */
    public void createModelTable(Long modelId, List<ModelField> fields) {
        modelDataDao.createTable(SqlSafeUtil.safeNumber(modelId));   // 4.3 固定列模板
        for (ModelField f : fields) addColumn(modelId, f);
    }

    /** 新增字段：ALTER ADD COLUMN（列类型必须来自 FieldTypeEnum，字段名过白名单） */
    public void addColumn(Long modelId, ModelField field) {
        String colType = FieldTypeEnum.valueOf(field.getFieldType().toUpperCase()).resolveColumnType(field.getMaxlength());
        if (colType == null) return;                                 // editor 不建列
        modelDataDao.addColumn(SqlSafeUtil.safeNumber(modelId),
                SqlSafeUtil.safeColumnName(field.getFieldName()),
                colType, field.getFieldLabel().replace("'", "''"));
    }

    public void dropColumn(Long modelId, String fieldName) { /* DROP COLUMN，fieldName 过 safeColumnName */ }
    public void dropTable(Long modelId) { /* 删除模型时 DROP TABLE IF EXISTS */ }
    /** 表是否存在（information_schema 查询，供懒补偿与删除前校验） */
    public boolean tableExists(Long modelId) { ... }
}
```

DDL 的 Mapper 写法（与项目 Dao.xml 风格一致，`${}` 只用于已过白名单的标识符）：

```xml
<update id="createTable">
    CREATE TABLE IF NOT EXISTS fly_cmodel_${modelId} ( ...4.3 固定列... ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
</update>
<update id="addColumn">
    ALTER TABLE fly_cmodel_${modelId} ADD COLUMN ${columnName} ${columnType} COMMENT '${comment}' DEFAULT NULL
</update>
<select id="tableExists" resultType="boolean">
    SELECT COUNT(*) > 0 FROM information_schema.tables
    WHERE table_schema = DATABASE() AND table_name = CONCAT('fly_cmodel_', #{modelId})
</select>
```

### 5.4 ModelDataService（动态 CRUD）

一条内容 = 主表一行（title/content + 固定列 + 自定义列）：

```java
@Service
public class ModelDataService {
    @Autowired private ModelDataDao modelDataDao;
    @Autowired private ModelFieldService modelFieldService;
    @Autowired private ModelService modelService;
    @Autowired private SnowFlake snowFlake;            // core/utils/SnowFlake
    @Autowired private SolrService solrService;        // 搜索同步（可选 is_search）

    @Transactional
    public DataVo insertData(Long modelId, Map<String, Object> form) {
        // 1. 模型启用校验；2. 字段元数据驱动校验（required/regex/maxlength/options）
        // 3. IMAGE/FILE 字段：校验 fly_images.id 存在；IMAGES/FILES 校验 JSON 数组内 id
        //    并调 fly_images 的 info_count +1（引用计数，删除时 -1）
        // 4. id = snowFlake.nextId()；short_url 生成（10位，参考 ArticleService 现有 short_url 逻辑），
        //    校验 fly_cmodel_{modelId} 内唯一
        // 5. EDITOR 字段值 → content 列；IMAGE → thumbnail 或独立列
        // 6. modelDataDao.insertData(动态列)；分类关联写 fly_model_category 关系或 category_id 直存
        // 7. afterCommit：is_search 字段 + title/description 同步 Solr
    }

    public PageVo<Map<String,Object>> selectPage(Long modelId, 查询参数) {
        // 动态 where：仅固定列 + is_filter=1 字段；排序字段白名单 + SqlSafeUtil；分页 PageVo
    }
    // findDataById（含附件对象展开）/ updateData / deleteData（status=3 软删，引用计数-1，Solr 删文档）
}
```

`ModelDataDao.xml` 动态 SQL 核心（**值一律 `#{}`，`${}` 仅限白名单标识符**）：

```xml
<insert id="insertData">
    INSERT INTO fly_cmodel_${modelId}
    <foreach collection="columns" item="c" open="(" separator="," close=")">`${c}`</foreach>
    VALUES
    <foreach collection="columns" item="c" open="(" separator="," close=")">#{values[c]}</foreach>
</insert>

<select id="selectPage" resultType="map">
    SELECT * FROM fly_cmodel_${modelId}
    <where>${whereSql}</where>
    ORDER BY ${orderBySql}
    LIMIT #{offset}, #{rows}
</select>
```

`whereSql` 必须由 Service 代码生成：字段名来自元数据白名单、参数用 `#{paramName}` 预编译占位（把参数也放进 values Map），禁止接收前端原始 SQL 片段。

### 5.6 vben 对接接口（新增，建议 `web/system/AdminApiController`）

存量登录 `/system/login`（页面）+ `/system/login_act`（POST 表单 + redirect）是页面流，SPA 用不了。为 vben 新增一组纯 JSON 接口：

| 接口 | 说明 |
|---|---|
| `POST /system/api/auth/login` | JSON 登录：校验 `fly_admin` 账密（复用现有加密校验逻辑）→ 生成 token（雪花/UUID）→ 存 Caffeine（TTL 约 2h，滑动续期）→ 返回 `{token, admin}`。**不依赖 Session** |
| `POST /system/api/auth/logout` | 删除 token |
| `GET /system/api/auth/current` | 当前管理员信息 + 所属角色组 |
| `GET /system/api/auth/menus` | **后端动态菜单树**（vben 后端路由模式）：固定菜单（模型管理/分类管理）+ **动态菜单**（遍历 `fly_model` 生成各模型"内容管理"入口，route_path=`/modelData/{code}`）——"后台控制一切"的体验点 |
| `GET /system/api/auth/permissions` | 当前管理员的 actionKey 集合 → 映射为 vben 权限码（见 8.4） |

**鉴权双轨桥接**：`AdminInterceptor` 增加一个分支——请求头带 `Authorization: Bearer {token}` 时从 Caffeine 解析管理员身份（等效现有 session 判定，校验失败返回 401 JSON）；无该头则走原 session 流程，存量页面零影响。

**CORS**：`filter/CorsFilter.java` 目前是空壳，需补全允许来源/头/方法（开发期放行 vben dev 端口）；生产用 nginx 同域反代后可不再依赖 CORS。

## 7. 前台路由与主题模板

### 7.1 前台路由（web/front/ModelController）

与现有 `ArticleController` 风格一致：

```
GET /{modelCode}/                          模型首页/列表（可带分页 /{modelCode}/p{page}/）
GET /{modelCode}/{categoryAlias}/          模型分类列表（fly_model_category 别名或 id）
GET /{modelCode}/{shortUrl}.html           详情页
```

控制器逻辑：`modelCode` 过 `SqlSafeUtil.safeModelCode` → 查模型缓存（不存在或禁用 → `templateService.get404()`）→ 定位主题模板 → 取数据（前台查询强制 `status=1`）→ FreeMarker 渲染。

### 7.2 主题模板组织（文件式，与现有 pc_theme 一致）

```
views/templates/pc_theme/defalut/
├── index.html / article/... 等现有模板（不动）
├── downloads/                    ← 新建模型时自动生成目录与默认模板
│   ├── list.html
│   └── detail.html
└── images/ ...
```

新建模型时 `ModelService` 自动在当前启用主题下创建 `{code}/list.html`、`{code}/detail.html` 默认模板文件（内容为内置骨架），管理员可通过后台"模板管理"或直接改文件定制；`fly_model.list_template/detail_template` 可覆盖默认路径。模板不存在时回退通用列表/详情骨架，再无则 404。

### 7.3 新增 FreeMarker 标签（web/tags，尖括号语法）

继承 `AbstractTagPlugin`（照抄 `Articlepage` 的参数解析模式），4 个标签：

| 标签类 | 模板用法 | 参数 |
|---|---|---|
| `ListModel` | `<@ListModel model="downloads" category="1" p="1" rows="10" orderby="create_time" order="desc">…</@ListModel>` | model(code)、category、p、rows、orderby（白名单）、order |
| `PageModel` | 同 ListModel + 总数/总页数（配合翻页） | 同上 |
| `InfoModel` | `<@InfoModel model="downloads" id="xxx" shortUrl="abc">…</@InfoModel>` | id 或 shortUrl |
| `FieldsModel` | `<@FieldsModel model="downloads">…</@FieldsModel>` | 输出字段元数据（详情页动态展示用） |

模板示例（**尖括号**，注意与 MxxSaas 的方括号不同）：

```ftl
<@ListModel model="downloads" category="${category.id}" p="${p!1}" rows="10">
<#list dataList as item>
<li>
    <a href="/downloads/${item.shortUrl}.html">${item.title}</a>
    <span>${(item.file_size)!''}MB</span>
</li>
</#list>
</@ListModel>
```

实现要点：标签内 `model code → id` 走 Caffeine 缓存；取数复用 `ModelDataService` 查询通道（与后台共用 where 构造器，前台额外强制 `status=1`）；IMAGE/FILE 字段在 Service 层展开为 `xxxObj`（含 img_url、img_name），模板零二次查询；模型表不存在时懒补偿（`CREATE TABLE IF NOT EXISTS` 幂等）。

## 8. 周边集成

### 8.1 附件（图片/下载模型底座）

- `image`/`file` 字段值 = `fly_images.id`；`images`/`files` = id JSON 数组。
- 引用计数：内容新增/删除/更新时维护 `fly_images.info_count`（+1/-1/差集调整），沿用其"使用次数"语义；`fly_images_info_merge` 如需反查引用关系可一并维护。
- 下载模型建议种子字段：`file`(file)、`file_size`(number)、`run_env`(textarea)、`demo_url`(input)；图片模型：`images`(images)、`shoot_time`(datetime)。
- 输出 URL：`fly_images.img_url` 直出（项目现状为本地存储路径）。

### 8.2 Solr 搜索

- 每模型一个 Solr core/集合，或在现有索引加 `model_id` 字段（看 SolrService 现有索引结构，倾向后者改动小）。
- 同步字段：`title` `description` + `is_search=1` 自定义字段 + `model_id` `status` 过滤维度。
- 时机：insert/update 事务提交后、delete 软删后删除文档；后台 `SolrAdminController` 增加"重建模型索引"入口。

### 8.3 缓存（Caffeine，config/EhCacheConfig）

| 缓存 | key | 失效 |
|---|---|---|
| 模型元数据 | `model:id_{id}`、`model:code_{code}`、`model:fields_{modelId}` | 模型/字段增删改 |
| 前台查询结果（可选） | `modeldata:{modelId}_{参数指纹}` | 该模型内容增删改、字段变更 |

沿用 EhCacheConfig 现有缓存管理器，新增 cache 区即可。

### 8.4 权限

第 4.5 节 SQL 必须执行，否则所有 `/system/model*` 接口 403。

**vben 权限码映射**：`/system/api/auth/permissions` 把当前管理员授权的 actionKey 集合转为权限码数组（如 `system:model:list`、`system:modelData:del`），vben 端用于路由 meta 与按钮显隐（`v-access` / 权限码判断）；**权威校验始终在后端 URL 白名单拦截器**，前端仅控制展示层。上线前用非超管组账号验证按钮粒度（列表可见、删除无权且接口 403）。

## 9. 安全规范（必读）

1. **DDL 白名单三件套**：进入 DDL 的只有——雪花数字 ID（`safeNumber`）、字段名（`safeColumnName`：小写字母开头正则 + 保留字黑名单 + 反引号）、列类型（仅 `FieldTypeEnum.resolveColumnType()` 产物）。COMMENT 文本转义单引号。**前端传的 field_type 只允许匹配枚举 code，column_type 一律后端推导。**
2. **DML 动态 SQL**：表名 = `fly_cmodel_` + 数字校验后的 modelId；值永远 `#{}`；`whereSql`/`orderBySql` 由 Service 依元数据生成（字段名白名单、参数预编译），禁止拼接前端原始输入。
3. **权限**：所有新接口插入 `fly_admin_permission`；URL 通配授权注意 `/system/model/*` 与 `/system/modelData/*` 的前缀包含关系（`/system/model/*` 会匹配 `/system/modelData/*` 吗？——不会，通配按 path 段匹配，但仍需实测确认拦截器行为）。
4. **内置保护**：`is_system=1` 禁删禁改 code；删除模型需二次确认并列明级联（DROP 表、删字段定义、删 Solr 文档）。
5. **XSS**：editor 字段入库前用 jsoup `Safelist.relaxed()` 清洗（项目已依赖 jsoup）；标题/摘要长度截断。
6. **资源上限**：模型数（默认 20）、每模型字段数（60）做配置上限，防 ALTER 风暴。
7. **字段变更兼容性**：修改字段类型仅允许同兼容组（varchar 加长、int→bigint）；跨组变更提示"需手动迁移数据"，禁止直接 DROP 再 ADD。
8. **事务**：DDL 放元数据保存成功之后执行（本项目无显式多表事务钩子，保持"先元数据后 DDL、DDL 幂等可重试"的顺序即可；避免在一个 @Transactional 里混合 DDL 与 DML——MySQL DDL 隐式提交会破坏回滚语义）。
